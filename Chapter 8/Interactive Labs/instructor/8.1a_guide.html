COP1035 · Python Programming · Lab 8.1a

Objects, state and interface: the makerspace laser engraver

Objectives

  • Use a Turtle object through its interface: instantiate it, then change its state with mutator methods
  • Generalize square and hexagon into one polygon function that works for any number of sides
  • Use accessor methods (position, heading, isdown) to save an object's state and restore it afterwards

Requirements

  1. R1 polygon repeats sides times: move forward length, then turn left 360 / sides degrees. No number of sides is hard-coded.
  2. R2 badge lifts the pen before travelling to (x, y), faces east (setheading(0)) and lowers the pen before drawing.
  3. R3 badge reads the turtle's position, heading and pen state with accessor methods before changing anything, and restores all three at the end: it travels back with the pen up, and lowers the pen only if it was down before.
  4. R4 The test program's badges burn no stray lines, and the turtle ends where and how it started. (verified by the program output)

Before you code: warm-up and model answers

  1. Run the starter. badge calls t.goto(x, y) on a brand-new turtle. Which line does the laser burn that isn't part of any badge, and which part of the turtle's state causes it?

    A straight line from the home position (0, 0) to the badge's corner (-100, 50). A new turtle's pen is down (isdown() is True), and goto draws whenever the pen is down, so moving to the corner burns a line.

  2. square turns 90 degrees four times and hexagon turns 60 degrees six times. What do the turns of each shape add up to, and what would one turn of a pentagon be?

    Both add up to 360 degrees, one full turn, so the turtle ends facing the way it started. A pentagon turns 360 / 5 = 72 degrees at each corner.

penturtle.py (read-only for students)
"""penturtle.py - a text-mode stand-in for turtle.Turtle.

It has the same method names as the Turtle methods in Table 8-2, so code
you write with it also runs in IDLE: change the import to
    from turtle import Turtle
Instead of opening a window, this Turtle keeps a log of the lines it draws.

Extras for the labs (NOT in the real Turtle):
    t.lines(), t.lineColors(), t.report()
"""
import math


def _tidy(value):
    """Rounds to 2 decimals and turns -0.0 into 0.0."""
    return round(value, 2) + 0.0


def _checkColor(args):
    """Returns the color given to pencolor/fillcolor, or raises ValueError."""
    if len(args) == 1 and isinstance(args[0], str):
        return args[0]
    if len(args) == 1 and isinstance(args[0], tuple):
        args = args[0]
    if len(args) != 3:
        raise ValueError("a color is a string or three RGB values, got " +
                         repr(args))
    for part in args:
        if not isinstance(part, int) or part < 0 or part > 255:
            raise ValueError("bad color sequence: " + repr(tuple(args)) +
                             " (each RGB component is an int from 0 to 255)")
    return tuple(args)


class _Screen:
    """The turtle's window: 300 by 200 pixels, as in the book's turtle.cfg."""

    def __init__(self):
        self._bg = "white"

    def window_width(self):
        return 300

    def window_height(self):
        return 200

    def bgcolor(self, *color):
        if not color:
            return self._bg
        self._bg = _checkColor(color)

    def colormode(self, mode=None):
        return 255


class Turtle:
    """A turtle that logs its lines instead of drawing them in a window."""

    def __init__(self):
        self._x = 0.0
        self._y = 0.0
        self._heading = 0.0
        self._down = True
        self._color = "black"
        self._fill = "black"
        self._width = 1
        self._visible = True
        self._filling = False
        self._lines = []
        self.screen = _Screen()

    # ---- accessor methods: report the state, change nothing ----
    def position(self):
        """Returns the current position (x, y)."""
        return (_tidy(self._x), _tidy(self._y))

    pos = position

    def xcor(self):
        return _tidy(self._x)

    def ycor(self):
        return _tidy(self._y)

    def heading(self):
        """Returns the current direction in degrees (0 east, 90 north)."""
        h = _tidy(self._heading % 360)
        return 0.0 if h == 360 else h

    def isdown(self):
        """Returns True if the pen is down."""
        return self._down

    def isvisible(self):
        return self._visible

    # ---- mutator methods: change the state ----
    def up(self):
        self._down = False

    penup = pu = up

    def down(self):
        self._down = True

    pendown = pd = down

    def setheading(self, degrees):
        self._heading = float(degrees)

    seth = setheading

    def left(self, degrees):
        self._heading += degrees

    lt = left

    def right(self, degrees):
        self._heading -= degrees

    rt = right

    def goto(self, x, y=None):
        if y is None:
            (x, y) = x
        self._moveTo(float(x), float(y))

    setpos = setposition = goto

    def forward(self, distance):
        angle = math.radians(self._heading)
        self._moveTo(self._x + distance * math.cos(angle),
                     self._y + distance * math.sin(angle))

    fd = forward

    def backward(self, distance):
        self.forward(-distance)

    back = bk = backward

    def home(self):
        self.goto(0, 0)
        self.setheading(0)

    def pencolor(self, *color):
        if not color:
            return self._color
        self._color = _checkColor(color)

    def fillcolor(self, *color):
        if not color:
            return self._fill
        self._fill = _checkColor(color)

    def width(self, pixels=None):
        if pixels is None:
            return self._width
        self._width = pixels

    pensize = width

    def begin_fill(self):
        self._filling = True

    def end_fill(self):
        self._filling = False

    def clear(self):
        """Erases the drawings; the turtle's state does not change."""
        self._lines = []

    def hideturtle(self):
        self._visible = False

    ht = hideturtle

    def showturtle(self):
        self._visible = True

    st = showturtle

    def speed(self, value=None):
        return 0

    def shape(self, name=None):
        return "classic"

    def _moveTo(self, x, y):
        start = (_tidy(self._x), _tidy(self._y))
        end = (_tidy(x), _tidy(y))
        if self._down and start != end:
            self._lines.append((start, end, self._color))
        self._x = x
        self._y = y

    # ---- extras for the labs (not in the real Turtle) ----
    def lines(self):
        """Returns the lines drawn so far as a list of (start, end) points."""
        return [(start, end) for (start, end, color) in self._lines]

    def lineColors(self):
        """Returns the pen color of each line drawn so far."""
        return [color for (start, end, color) in self._lines]

    def report(self):
        """Returns a short summary of the drawing."""
        total = 0.0
        for ((x1, y1), (x2, y2), color) in self._lines:
            total += math.hypot(x2 - x1, y2 - y1)
        return ("Lines drawn: " + str(len(self._lines)) + ", total length " +
                str(_tidy(total)) + " pixels")

Solution

badges.py
"""badges.py - burn badge outlines with the makerspace laser engraver.

The engraver is driven by a Turtle object: whenever its pen is down,
the laser burns.
"""
from penturtle import Turtle   # in IDLE: from turtle import Turtle


def square(t, length):
    """Draws a square with the given length, from t's position and heading."""
    for count in range(4):
        t.forward(length)
        t.left(90)


def hexagon(t, length):
    """Draws a hexagon with the given length, from t's position and heading."""
    for count in range(6):
        t.forward(length)
        t.left(60)


def polygon(t, sides, length):
    """Draws a regular polygon with the given number of sides and
    side length."""
    for count in range(sides):
        t.forward(length)
        t.left(360 / sides)


def badge(t, x, y, sides, length):
    """Burns a badge outline with its first corner at (x, y) and its
    first side facing east. Leaves t as it found it: same position,
    heading and pen state."""
    (oldX, oldY) = t.position()
    oldHeading = t.heading()
    wasDown = t.isdown()
    t.up()
    t.goto(x, y)
    t.setheading(0)
    t.down()
    polygon(t, sides, length)
    t.up()
    t.goto(oldX, oldY)
    t.setheading(oldHeading)
    if wasDown:
        t.down()


def main():
    """Burns two badges and prints what the laser did."""
    t = Turtle()
    badge(t, -100, 50, 6, 30)
    badge(t, 40, 50, 5, 30)
    print(t.report())
    print("Laser head at", t.position(), "facing", t.heading())


if __name__ == "__main__":
    main()

Walkthrough

polygon is the reading's Exercise 8-1, question 4: the only differences between square and hexagon are the loop count and the turn, and for a regular polygon the turns add up to one full circle, so each one is 360 / sides. In badge, the three accessor calls must come first, because every mutator after them changes the state they report. goto draws whenever the pen is down, so the pen goes up before both trips (to the badge and back). Restoring the pen with if wasDown: t.down() matters: a caller that had lifted the pen expects it still up afterwards. Equivalent forms: t.penup()/t.pendown(), t.xcor()/t.ycor() instead of position(), or if not wasDown: t.up() placed after an unconditional t.down().

Messages students see when a check fails

C1 · polygon loops sides times

Loop for count in range(sides): so the same function draws a triangle, a square or a hexagon. A fixed number such as range(6) only ever draws one shape.

C2 · polygon turns 360 / sides

A regular polygon's turns add up to 360 degrees, so each turn is 360 / sides (90 for a square, 60 for a hexagon). Compute it from the argument rather than writing one angle.

C3 · pen up before travelling to (x, y)

goto draws a line whenever the pen is down, and a new turtle's pen starts down. Call t.up() before t.goto(x, y) so the laser travels without burning.

C4 · faces east and lowers the pen before drawing

Point the turtle east with t.setheading(0) (so every badge has the same orientation) and call t.down() before polygon(...), or nothing gets burned.

C5 · saves the state with accessor methods

Store the turtle's state before you change it: t.position(), t.heading() and t.isdown() are accessor methods; they report the state without changing it.

C6 · restores position and heading

After the polygon, lift the pen, goto the saved position and setheading to the saved heading (a variable, not a number). Without the lift, the trip back burns a second scar.

C7 · restores the pen only as it was

Use the pen state you saved: if wasDown: t.down(). Always lowering it would surprise a caller who had lifted the pen; always leaving it up would surprise one who hadn't.

Progressive hints

  1. Start with polygon: compare square and hexagon line by line. Which two numbers change, and how are they related?

  2. In badge, a turtle forgets nothing, but it only tells you its state when you ask. Ask (with accessor methods) before the first mutator call, and keep the answers in variables.

  3. Both trips use goto, and goto burns whenever the pen is down. The pen needs to be up for the trip to the badge and for the trip back; only the final pen state depends on what you saved.

Reflection: questions and model answers

  1. Which methods in your badge are accessors and which are mutators? Why must the accessor calls come before the first mutator?

    position, heading and isdown are accessors: they report the state without changing it. up, goto, setheading, down, forward and left are mutators: they change it. The accessors must run first because each mutator changes the state they report; after t.up() and t.goto(x, y), position() and isdown() would return the badge's corner and False instead of the original values.

  2. Your code ran with penturtle.Turtle, and it will run unchanged with turtle.Turtle in IDLE. What does that say about how programmers use objects through their interfaces?

    Your functions only call methods by name and rely on what each method is documented to do. They never look inside the object. Any class with the same interface (the same method headers and behavior) can stand in, so the drawing code doesn't care whether the turtle draws on screen or records lines. This is why an interface should give just enough information to use the object.

  3. Why should a helper such as badge leave the turtle as it found it, instead of leaving it at the badge's last corner?

    The caller decides where the turtle is and which way it faces, and the next command assumes that state hasn't changed. If badge moved or rotated the turtle, every later shape would be shifted or rotated, as happened with the ruined board. Restoring the state makes badge safe to call in any order and from any other function.
