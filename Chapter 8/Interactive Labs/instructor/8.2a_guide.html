Traversing a grid of pixels: student ID photo filters

Objectives

  • Visit every pixel of an image of any size with a row-major nested loop, using screen coordinates (x is the column, y is the row)
  • Unpack a pixel's (r, g, b) tuple, compute with its parts and set a new tuple
  • Convert to grayscale with luminance weights, and generalize black and white into a two-color filter

Requirements

  1. R1 grayscale visits every pixel of any image in row-major order: the outer loop goes through the rows (y up to getHeight()), the inner loop through the columns (x up to getWidth()).
  2. R2 grayscale uses the luminance weights: red times 0.299, green times 0.587, blue times 0.114, each converted with int, and sets the pixel to (lum, lum, lum).
  3. R3 posterize(image, color) visits every pixel and decides with the RGB average: below 128 is dark, 128 or above is light.
  4. R4 posterize sets dark pixels to the color argument and light pixels to white (255, 255, 255). No color is hard-coded for dark pixels.
  5. R5 The test program's grayscale values, the 1-by-5 strip and the poster match. (verified by the program output)

Before you code: warm-up and model answers

  1. The sample photo is 4 pixels wide and 3 tall. The starter's outer loop is for y in range(image.getWidth()) and the inner one for x in range(image.getHeight()). Which getPixel call fails first, and which column is never visited?

    getPixel(0, 3) fails first: y runs 0 to 3 because the width is 4, but the rows are only 0 to 2. Column x = 3 is never visited, because x only goes to 2 (the height minus 1).

  2. With the plain average, pure green (0, 255, 0) and pure blue (0, 0, 255) both become the same gray. Which one looks brighter to the human eye?

    Green. The eye is most sensitive to green and least to blue, so averaging makes blue areas too light and green areas too dark. Both average to 85.

images.py (read-only for students)
"""images.py - a text-mode stand-in for the book's images module.

The Image class has the same methods as Table 8-4 (getWidth, getHeight,
getPixel, setPixel, clone, draw, save), so functions you write with it also
run with the real images module. Two differences:
  - Build an image from rows of RGB tuples, Image(rows), instead of a GIF file
    (Image(width, height) still makes a blank image, as in the book).
  - draw() prints the pixels instead of opening a window; a blank (transparent)
    pixel prints as  --  .
Extra for the labs (NOT in the real module): image.blankPixels().
"""


class Image:
    """A grid of RGB pixels with (0, 0) at the upper-left corner."""

    def __init__(self, *args):
        self.filename = ""
        if len(args) == 2 and all(isinstance(a, int) for a in args):
            (width, height) = args
            self._pixels = [[None] * width for y in range(height)]
        elif len(args) == 1 and isinstance(args[0], list):
            self._pixels = [list(row) for row in args[0]]
            for row in self._pixels:
                for p in row:
                    _checkRGB(p)
        else:
            raise ValueError("this stand-in builds Image(width, height) or "
                             "Image(rows); it cannot open image files")

    def getWidth(self):
        """Returns the width in pixels."""
        return len(self._pixels[0]) if self._pixels else 0

    def getHeight(self):
        """Returns the height in pixels."""
        return len(self._pixels)

    def getPixel(self, x, y):
        """Returns the (r, g, b) tuple at column x, row y."""
        self._checkPosition(x, y)
        p = self._pixels[y][x]
        return (0, 0, 0) if p is None else p

    def setPixel(self, x, y, rgb):
        """Replaces the pixel at column x, row y with the tuple (r, g, b)."""
        self._checkPosition(x, y)
        _checkRGB(rgb)
        self._pixels[y][x] = tuple(rgb)

    def clone(self):
        """Returns a new image with the same pixels; changing one leaves
        the other alone."""
        copy = Image(self.getWidth(), self.getHeight())
        copy._pixels = [list(row) for row in self._pixels]
        return copy

    def draw(self):
        """Prints the pixels, one row per line (the real one opens a window)."""
        for row in self._pixels:
            cells = []
            for p in row:
                if p is None:
                    cells.append("     --     ")
                else:
                    cells.append("(%3d,%3d,%3d)" % p)
            print(" ".join(cells))

    def save(self, filename=None):
        """Records the filename (the real module writes a GIF file)."""
        if filename is not None:
            if not filename.endswith(".gif"):
                filename += ".gif"
            self.filename = filename

    def blankPixels(self):
        """Returns how many pixels have never been given a color."""
        return sum(row.count(None) for row in self._pixels)

    def __str__(self):
        return ("Filename: " + self.filename +
                "\nWidth: " + str(self.getWidth()) +
                "\nHeight: " + str(self.getHeight()))

    def _checkPosition(self, x, y):
        w = self.getWidth()
        h = self.getHeight()
        inside = (isinstance(x, int) and isinstance(y, int) and
                  0 <= x < w and 0 <= y < h)
        if not inside:
            raise IndexError("pixel (" + str(x) + ", " + str(y) +
                             ") is outside this " + str(w) + " x " + str(h) +
                             " image: x goes 0 to " + str(w - 1) +
                             ", y goes 0 to " + str(h - 1))


def _checkRGB(rgb):
    """Raises ValueError unless rgb is three ints from 0 to 255."""
    if not (isinstance(rgb, tuple) and len(rgb) == 3 and
            all(isinstance(c, int) and 0 <= c <= 255 for c in rgb)):
        raise ValueError("a pixel is a tuple of three ints from 0 to 255, "
                         "got " + repr(rgb))

Solution

filters.py
"""filters.py - prepare student ID photos for the card printer and
the event poster."""
from images import Image   # the real images module has the same Image methods


def grayscale(image):
    """Converts the argument image to grayscale (changes it in place)."""
    for y in range(image.getHeight()):
        for x in range(image.getWidth()):
            (r, g, b) = image.getPixel(x, y)
            r = int(r * 0.299)
            g = int(g * 0.587)
            b = int(b * 0.114)
            lum = r + g + b
            image.setPixel(x, y, (lum, lum, lum))


def posterize(image, color):
    """Converts the argument image to two colors (changes it in place):
    dark pixels become the given color, light pixels become white."""
    whitePixel = (255, 255, 255)
    for y in range(image.getHeight()):
        for x in range(image.getWidth()):
            (r, g, b) = image.getPixel(x, y)
            average = (r + g + b) // 3
            if average < 128:
                image.setPixel(x, y, color)
            else:
                image.setPixel(x, y, whitePixel)


def samplePhoto():
    """Returns a small 4-by-3 test photo."""
    return Image([
        [(255, 0, 0), (0, 255, 0), (0, 0, 255), (255, 255, 255)],
        [(200, 180, 40), (10, 20, 30), (128, 128, 128), (90, 200, 250)],
        [(0, 0, 0), (127, 128, 129), (250, 100, 50), (60, 60, 200)]])


def main():
    """Shows a sample photo before and after each filter."""
    photo = samplePhoto()
    print(photo)
    photo.draw()
    print("Grayscale:")
    grayscale(photo)
    photo.draw()
    print("Poster in school navy:")
    poster = samplePhoto()
    posterize(poster, (0, 51, 102))
    poster.draw()


if __name__ == "__main__":
    main()

Walkthrough

Screen coordinates are (column, row): getPixel(x, y) takes x up to getWidth() - 1 and y up to getHeight() - 1. The starter's loops took their ranges from the wrong dimension, which is invisible on a square image and fails on the first wide one (y reaches 3 on a 3-row image). The weights follow the reading's grayscale; truncating each product separately is why white becomes (254, 254, 254): 76 + 149 + 29. posterize is the reading's blackAndWhite with the dark color taken from a parameter. A column-major traversal (x outer, y inner) also visits every pixel and is accepted, as are width = image.getWidth() style variables. The stand-in rejects floats in a pixel, so a missing int shows up as a clear error.

Messages students see when a check fails

C1 · rows come from the height, columns from the width

In screen coordinates, x is the column and y is the row. Loop for y in range(image.getHeight()): and inside it for x in range(image.getWidth()):, so x never passes the last column and y never passes the last row.

C2 · luminance weights

Weight the components by how bright they look to the eye: r * 0.299, g * 0.587, b * 0.114. Green looks brightest and blue darkest, so a plain average misjudges them.

C3 · integers, not the plain average

Replace the // 3 average with the weighted sum, and convert with int(...): a pixel's components must be integers, and 0.299 * r is a float.

C4 · every pixel, judged by its average

Use the same nested loops as grayscale, compute (r + g + b) // 3 for each pixel, and compare it with 128, as the reading's blackAndWhite does.

C5 · dark pixels get the color argument

Pass the parameter itself: image.setPixel(x, y, color). That is what makes posterize a generalization of blackAndWhite: the caller chooses the dark color.

Reflection: questions and model answers

  1. White (255, 255, 255) came out as (254, 254, 254). Explain exactly where the missing 1 went.

    Each product is truncated separately with int: int(255 * 0.299) = 76, int(255 * 0.587) = 149 and int(255 * 0.114) = 29, which add up to 254. The fractions .245, .685 and .07 that were dropped add up to about 1. Rounding the total, int(r * 0.299 + g * 0.587 + b * 0.114 + 0.5), would keep white at 255.

  2. grayscale and posterize change the image they receive and return nothing. When is that a good design, and when would you rather return a new image?

    Changing the image in place saves memory and suits a pipeline where the original isn't needed again. But it destroys the original, so if the program must keep it (to compare, undo, or make the card and the poster from the same photo) it should work on a clone or return a new image. That is why main builds a second samplePhoto for the poster.

  3. Why does a pixel at average 127 become navy while one at 128 becomes white? Is 128 a good threshold for every photo?

    The test is average < 128, so 127 counts as dark and 128 as light; 128 is the midpoint of 0 to 255. It's a reasonable default, but a dark photo would turn almost all navy and a bright one almost all white. A better poster might take the threshold as a parameter or use the photo's own average brightness.
