COP1035 · Python Programming · Lab 5.2

Pizza night for the programming club

Objectives

  • Define a function with a header, parameters, a docstring and a return statement
  • Explain the difference between returning a value and printing it, and write a Boolean function
  • Organise a script around a main function that runs only when the file is run as a program

Requirements

  1. R1 Define slices_needed(people, slices_each): two parameters, a docstring, and it returns the total number of slices.
  2. R2 order_cost(pizzas, price) returns the cost (pizzas times price) to its caller. It prints nothing.
  3. R3 within_budget(cost, budget) is a Boolean function: it returns True when cost is less than or equal to budget, and False otherwise.
  4. R4 main gets slices, pizzas, cost and affordable by calling the four functions with the right arguments. It does none of the arithmetic itself.
  5. R5 main() is called only when the file is run as a program (the if __name__ == "__main__": entry point), so importing the module asks no questions.
  6. R6 The test program can import the functions, combine their results and run main with the answers 13, 2, 11.5 and 40. (verified by the program output)

Before you code: warm-up and model answers

  1. pizzas_needed is finished. Trace pizzas_needed(26) and pizzas_needed(24) by hand. Why is slices // SLICES_PER_PIZZA alone not enough?

    pizzas_needed(26): 26 // 8 is 3, the remainder 26 % 8 is 2, which is not 0, so one more pizza is added and it returns 4. pizzas_needed(24): 24 // 8 is 3 and the remainder is 0, so it returns 3. Integer division alone rounds down, which would leave two people without a slice.

  2. In the starter, what appears on the screen when cost = order_cost(4, 11.5) runs, and what value ends up in cost?

    46.0 appears on the screen because the function prints it. But the function has no return statement, so it returns None, and cost holds None. The number was shown to a person but never given back to the program.

Solution

pizza_night.py
"""pizza_night.py - plans the order for the programming club's pizza night."""

SLICES_PER_PIZZA = 8


def pizzas_needed(slices):
    """Given: return how many whole pizzas are needed to cover slices."""
    pizzas = slices // SLICES_PER_PIZZA
    if slices % SLICES_PER_PIZZA != 0:
        pizzas += 1
    return pizzas


def slices_needed(people, slices_each):
    """Return the total number of slices for people who eat slices_each each."""
    return people * slices_each


def order_cost(pizzas, price):
    """Return the cost of pizzas at price each."""
    return pizzas * price


def within_budget(cost, budget):
    """Return True if cost is no more than budget, or False otherwise."""
    if cost <= budget:
        return True
    else:
        return False


def main():
    """Ask for the numbers, call the functions and print the plan."""
    people = int(input("How many people? "))
    slices_each = int(input("Slices per person? "))
    price = float(input("Price per pizza? "))
    budget = float(input("Budget? "))
    print()

    slices = slices_needed(people, slices_each)
    pizzas = pizzas_needed(slices)
    cost = order_cost(pizzas, price)
    affordable = within_budget(cost, budget)

    print("Order", pizzas, "pizzas for", slices, "slices. Cost:", cost)
    if affordable:
        print("Within budget.")
    else:
        print("Over budget: collect more money.")


# The entry point for program execution
if __name__ == "__main__":
    main()

Walkthrough

A parameter is the name in the header; the argument is the value a call passes in, matched by position. return sends a value back to the caller, who can store it, compare it or add it to another result; print only shows text to a person and the function then returns None, which is why order_cost(2, 10) + order_cost(1, 10) crashed in the starter. within_budget may use if/else with two exit points, as the textbook's odd does, or simply return cost <= budget, because the comparison already evaluates to True or False. In main, each result feeds the next call. When the file is imported, __name__ is the module's name, so the if keeps main from running; when the file is run directly, __name__ is "__main__".

Messages students see when a check fails

C1 · slices_needed is defined with two parameters

Write a header with the keyword def, the name slices_needed, two parameters in parentheses separated by a comma, and a colon. The body goes on the next lines, indented.

C2 · slices_needed has a docstring

Make the first line of the body a docstring in triple quotes that says what the function returns. It is what help(slices_needed) displays to whoever uses your function.

C3 · slices_needed returns the product

The function must hand the total back with a return statement. Don't print inside it: main decides what appears on the screen.

C4 · order_cost returns instead of printing

print shows the number to a person, and then the function returns None, so cost = order_cost(4, 11.5) stores None. Replace the print with a return statement so the caller receives the value.

C5 · within_budget returns the result of a comparison

Compare cost with budget and return True or False. A cost exactly equal to the budget is still within it, so think about which comparison operator you need.

C6 · main calls all four functions and leaves the arithmetic to them

Replace each placeholder value with a call: slices_needed, then pizzas_needed, then order_cost, then within_budget. The value one call returns becomes an argument of the next. main should not multiply, divide or compare: that work already lives in the functions, so a change in how the cost is computed touches only order_cost.

C7 · main is called from the entry point

End the script with the entry point from the reading: an if statement that compares __name__ with "__main__" and calls main() in its body.

C8 · No call to main() outside the entry point

A main() call at the left margin runs every time the file is loaded, even when another script only wants to import your functions. Indent it under the if __name__ == "__main__": line.

Reflection: questions and model answers

  1. Pick one of the calls you wrote in main and name its arguments and the parameters they are matched with. What decides which argument goes to which parameter?

    For example, in cost = order_cost(pizzas, price) the arguments are the values of main's variables pizzas and price; they are matched with the parameters pizzas and price in the header of order_cost. Position decides the match, not the names: the first argument goes to the first parameter and the second to the second.

  2. The test program prints Imported without starting the program. before anything else. What would it have printed first with a bare main() at the end of your file, and why?

    It would have shown the four questions first (and used up the typed answers), because importing a module runs all of its top-level statements, including a bare call to main. With the entry point, __name__ is the module's name 'pizza_night' during an import, not '__main__', so main is not called until the test program calls it.

  3. order_cost now returns its result instead of printing it. Give two things the test program does with that returned value that would be impossible if the function only printed.

    It stores the value in a variable and passes it to within_budget three times, and it adds the results of two calls together (order_cost(2, 10) + order_cost(1, 10)). A printed number is only text on the screen; a returned value can be stored, compared, passed to another function or used in arithmetic.
