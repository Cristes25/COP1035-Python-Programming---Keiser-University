COP1035 · Python Programming · Lab 5.3

Which course needs another tutor?

Objectives

  • Read a value from a dictionary safely when the key may be missing, using get with a default
  • Build a dictionary from scratch that counts how often each value occurs in a list
  • Traverse a dictionary in a chosen order by sorting a list of its keys, and remove a key safely with pop

Requirements

  1. R1 room_for(course) returns the room from the ROOMS lookup table, or "Front desk" when the course is not a key in it. It never raises a KeyError.
  2. R2 tally(requests) returns a dictionary built from scratch in which each course in the list is a key and its value is the number of times it was requested.
  3. R3 busiest(counts) returns the course (the key) with the highest count. The dictionary has at least one course; if two courses tie, either may be returned.
  4. R4 report(counts) prints one line per course, with the courses in alphabetical order, whatever order they were added in.
  5. R5 close_course(counts, course) removes the course from the dictionary and returns its count, or returns 0 when the course is not in the dictionary.
  6. R6 The weekly log in the test program is counted, reported and closed correctly. (verified by the program output)

Before you code: warm-up and model answers

  1. ROOMS is a dictionary literal. Name one of its keys and that key's value. With the starter code, what does room_for("MAC1105") return, and what happens with room_for("STA2023")?

    For example the key 'COP1035' has the value 'Lab 2'. room_for('MAC1105') returns 'Room 14'. 'STA2023' is not a key in ROOMS, so the subscript raises a KeyError and the program stops.

  2. In the starter's report, what is the loop variable course bound to on each pass: a key, a value or a pair? How does the loop reach the count?

    A for loop over a dictionary binds the variable to each key. The count is the value associated with that key, obtained with the subscript counts[course].

Solution

demand.py
"""demand.py - counts which courses students ask the tutoring center about."""

# A lookup table: the room where each course is tutored.
ROOMS = {"COP1035": "Lab 2", "MAC1105": "Room 14", "ENC1101": "Room 9"}


def room_for(course):
    """Return the room for course, or "Front desk" if the course has no room yet."""
    return ROOMS.get(course, "Front desk")


def tally(requests):
    """Return a dictionary that maps each course in requests to its count."""
    counts = {}
    for course in requests:
        counts[course] = counts.get(course, 0) + 1
    return counts


def busiest(counts):
    """Return the course with the most requests."""
    most = max(counts.values())
    for course in counts:
        if counts[course] == most:
            return course


def report(counts):
    """Print one line per course, in alphabetical order: the course, then its count."""
    courses = list(counts.keys())
    courses.sort()
    for course in courses:
        print(course, counts[course])


def close_course(counts, course):
    """Remove course from counts and return its count (0 if it is not there)."""
    return counts.pop(course, 0)

Walkthrough

A subscript with a missing key raises KeyError; get(key, default) returns the default instead, so room_for needs no if. In tally, the statement counts[course] = ... inserts the key the first time a course appears and replaces its value every time after that; get(course, 0) supplies the starting count for a course not seen before. The textbook's mode example does the same with get(word, None) and an if. busiest finds the largest value with max(counts.values()) and then looks for a key that has it. Dictionary order should not be relied on, so report sorts a list of the keys first (and must not write courses = courses.sort()). pop(key, default) removes the key and returns its value, or returns the default when the key is absent.

Messages students see when a check fails

C1 · room_for handles a missing course

ROOMS[course] raises a KeyError when the course is not a key. Use the dictionary method that takes a key and a default value, or test with in before using the subscript.

C2 · tally visits every request

Loop over the list requests so that every logged course is counted once.

C3 · tally reads the current count safely

The first time a course appears it is not yet a key, so counts[course] + 1 raises a KeyError. Ask for the current count with get and a default, or test with in to tell a new course from one already seen.

C4 · tally stores the count under the course

Store the new count with the subscript on the left of the assignment. The same statement inserts a new key or replaces the value at an existing key.

C5 · busiest finds the highest count

Find the largest number of requests first. max accepts a collection of values, and a dictionary can give you all of its values.

C6 · busiest returns a course

The coordinator needs the course code back, not the count. Traverse the keys and return the one whose value equals the highest count.

C7 · report sorts the keys before printing

The order of a dictionary's entries is not something to rely on. Get a list of the keys, sort that list, and traverse it. Remember from Lab 5.1b that sort() returns None, so call it on its own line.

C8 · close_course removes the key safely

pop with only a key raises a KeyError when the key is absent. Give pop a second argument, the value to return when the course is not in the dictionary.

Reflection: questions and model answers

  1. In tally, one statement both adds a course the first time it appears and updates it every time after. Explain how counts[course] = ... does both jobs, and what the default value in get contributes the first time.

    The subscript assignment inserts the key and value when the key is absent and replaces the value when the key already exists. The first time a course appears, get returns the default 0 instead of raising an error, so the stored count is 0 + 1 = 1. On later appearances get returns the current count, and one more than that replaces it.

  2. You could have kept the counts in two parallel lists, as the gradebook in Lab 5.1b did with names and scores. Why is a dictionary a better fit here? Use the words position and association.

    With parallel lists the only link between a course and its count is that they share a position, so every update means searching one list for the course's index and then using it in the other, and any reordering breaks the link. A dictionary stores the association itself: the course is the key and the count is its value, so the count is found directly from the course and position does not matter.

  3. room_for and close_course both return a default when the key is missing instead of letting the program stop with a KeyError. Why is that the right choice for the front desk? Describe a situation where stopping with an error would be the better choice.

    A request for a course without a room, or closing a course nobody asked about, is a normal event at the front desk, and a sensible answer exists (send the student to the front desk; zero requests). Stopping would lose the week's counts for nothing. An error is better when a missing key means the data or the program is wrong and continuing would hide it, for example looking up the price of a product code that should always exist: a made-up default price would be worse than stopping.
