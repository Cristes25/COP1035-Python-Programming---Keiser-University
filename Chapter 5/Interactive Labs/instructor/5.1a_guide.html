COP1035 · Python Programming · Lab 5.1a

The tutoring waitlist

Objectives

  • Add and remove list elements at either end with append, insert and pop
  • Find an element's position safely by testing with in before calling index
  • Replace the elements of a list with a loop over its indexes, and explain why a loop over the elements can't do it

Requirements

  1. R1 join(queue, name) adds name at the end of the list it receives, and join_with_appointment(queue, name) adds it at the front. Both change the caller's list; neither builds a new one.
  2. R2 call_next(queue) removes and returns the student at the front (index 0). If nobody is waiting, it returns None instead of crashing.
  3. R3 position(queue, name) returns the place in line counting from 1, or -1 when name is not in the queue. It never raises an error.
  4. R4 clean_up(queue) replaces each name inside the list with its tidy form (" dana WHITE" becomes "Dana White").
  5. R5 The waitlist behaves correctly through the whole afternoon in the test program. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter code and queue = ["Ana", "Ben", "Cy"], who does call_next(queue) return? Why is that unfair to the students in line?

    It returns 'Cy'. pop() with no argument removes and returns the last element, so the student who arrived last is helped first while Ana, at index 0, keeps waiting.

  2. The starter's clean_up loop runs with no error. After it finishes, has the list changed? Predict first, then explain what name = ... actually changes.

    No, the list is unchanged. On each pass the variable name refers to one element. Strings are immutable, so strip().title() builds a new string, and the assignment only makes the variable name refer to that new string. Nothing is assigned to a position in the list.

Solution

waitlist.py
"""waitlist.py - the walk-in queue at the campus tutoring center."""


def join(queue, name):
    """Add name to the end of the queue."""
    queue.append(name)


def join_with_appointment(queue, name):
    """Put name at the front of the queue."""
    queue.insert(0, name)


def call_next(queue):
    """Remove and return the student at the front, or None if nobody is waiting."""
    if len(queue) == 0:
        return None
    return queue.pop(0)


def position(queue, name):
    """Return name's place in line (1 is the front), or -1 if name is not waiting."""
    if name in queue:
        return queue.index(name) + 1
    else:
        return -1


def clean_up(queue):
    """Tidy every name in the queue: no outer spaces, Title Case."""
    for index in range(len(queue)):
        queue[index] = queue[index].strip().title()

Walkthrough

append and insert are mutators: they change the list object the caller passed in and return None, so the functions need no return. pop() with no argument removes the last element; the front of the line is pop(0), and pop raises an error on an empty list, so the length is tested first. Unlike the string method find, index raises an error when the element is absent, which is why the textbook tests with in first. In clean_up, the loop variable of for name in queue is only a name for each element; assigning to it never touches the list. A subscript on the left of = targets a position in the list, so the loop has to run over the indexes.

Messages students see when a check fails

C1 · join adds to the end of the same list

Use the list method that adds one element at the end of queue. Writing queue = queue + [name] builds a new list and leaves the front desk's list unchanged, because + returns a new list while a mutator method changes the list it is called on.

C2 · join_with_appointment inserts at index 0

The front of the line is index 0. insert(index, element) places the new element at that index and shifts everyone else one position to the right.

C3 · call_next removes the front of the line

pop() with no argument removes the last element, so the student who arrived last is helped first. Give pop the index of the front of the line.

C4 · call_next handles an empty queue

pop raises an error when the list is empty. Test the length of queue first and return None when nobody is waiting.

C5 · position tests for presence before searching

index raises an error when the element is not in the list (it does not return -1 the way the string method find does). Test with the in operator first, and return -1 when the name is absent.

C6 · position counts from 1

Indexes start at 0, but people count their place in line from 1. Add 1 to the index you return.

C7 · clean_up assigns to positions in the list

name = name.strip().title() only makes the variable name refer to a new string; the list still holds the old one. To replace an element, the subscript must be on the left of the =, so the loop has to run over the indexes, not over the elements.

Reflection: questions and model answers

  1. join has no return statement, yet after join(queue, "Mei Chen") the test program's list is longer. Explain how, using the word mutator. What would print(join(queue, "Ana")) display?

    append is a mutator: it changes the internal state of the list object it is called on, and the function received the same list object the test program uses, so the change is visible there. A function with no return statement returns None, so the print would display None (after adding Ana to the list).

  2. For strings, find returns -1 when the text is missing. Why does position need the in test before index? What would the front desk see without it when they look up a student who already left?

    The list method index raises an error (an exception) when the element is not found instead of returning -1. Without the in test the program would stop with a ValueError the moment someone looked up a name that is not in line. Testing first lets the function return -1, which the caller can handle.

  3. Why does replacing every element need a loop over range(len(queue)) when printing every element works fine with for name in queue?

    Printing only reads each element, and the loop variable gives the value. Replacing needs to say which position in the list receives the new value, and only the subscript queue[index] on the left of the assignment names a position. The index is needed to access the positions for the replacements.
