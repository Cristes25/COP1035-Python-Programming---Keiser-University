A gradebook that keeps its order

Objectives

  • Recognise when two variables are aliases for one list and predict the side effect of changing it
  • Copy a list before sorting it, and explain why aList = aList.sort() loses the list
  • Tell object identity (is) from structural equivalence (==), and write a one-element tuple

Requirements

  1. R1 median(scores) returns the median and leaves the caller's list exactly as it was: it sorts a copy, and it does not store the result of sort().
  2. R2 drop_lowest(scores) removes the lowest score from the caller's list itself, keeps the other scores in their positions, and returns the removed value.
  3. R3 same_list(a, b) returns True only when both names refer to the same list object, not when two different lists happen to have equal contents.
  4. R4 EXTRA_CREDIT is a tuple that contains the single quiz number 4.
  5. R5 In the test program, the names and scores still line up after the median is computed, and the dropped score disappears from every alias of the gradebook. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter's median, after the line ordered = scores runs, how many list objects exist: one or two? What does your answer mean for the instructor's quiz list when ordered gets sorted?

    One. Assignment does not copy a list; it makes ordered a second name (an alias) for the same list object. Sorting ordered therefore sorts the instructor's quiz list as a side effect, so the scores no longer sit at the same positions as their students' names.

  2. The next line is ordered = ordered.sort(). What value does ordered hold afterwards, and why does the following line, len(ordered), crash?

    None. sort is a mutator: it sorts the list in place and returns None, so the assignment replaces the reference to the list with None. len(None) raises a TypeError because None has no length.

Solution

gradebook.py
"""gradebook.py - quiz statistics that must not disturb the gradebook."""

# Quiz numbers that count as extra credit. There is only one so far.
EXTRA_CREDIT = (4,)


def median(scores):
    """Return the median of scores. The caller's list must keep its order."""
    ordered = list(scores)
    ordered.sort()
    midpoint = len(ordered) // 2
    if len(ordered) % 2 == 1:
        return ordered[midpoint]
    else:
        return (ordered[midpoint] + ordered[midpoint - 1]) / 2


def drop_lowest(scores):
    """Remove the lowest score from the caller's list and return it."""
    lowest = min(scores)
    scores.pop(scores.index(lowest))
    return lowest


def same_list(a, b):
    """Return True only if a and b are two names for the same list object."""
    return a is b


def is_extra_credit(quiz_number):
    """Given: True if quiz_number is one of the extra-credit quizzes."""
    return quiz_number in EXTRA_CREDIT

Walkthrough

ordered = scores creates an alias: one list object with two names, so sorting ordered reorders the instructor's quiz list and breaks the pairing with names. list(scores) (or scores[:]) builds a new list with the same elements. sort is a mutator and returns None, so ordered = ordered.sort() sorts the list and then throws away the only reference to it. drop_lowest is the opposite case: the side effect is the purpose, so it uses a mutator on the parameter and never rebinds or sorts it. is tests object identity, == structural equivalence. (4) is just the integer 4 in parentheses; the comma in (4,) is what makes a tuple.

Messages students see when a check fails

C1 · median works on a copy of the list

ordered = scores does not copy anything: both names now refer to the same list object, so sorting one sorts the instructor's gradebook too. Build a new list from scores (the textbook shows a one-line way with the list function) and sort that.

C2 · median does not store the result of sort()

sort is a mutator: it rearranges the list in place and returns None. Assigning its result makes your variable None, and the sorted list is lost. Call sort() as a statement on its own line.

C3 · drop_lowest removes from the caller's list

Remove the element from scores itself with a mutator such as pop. Don't sort scores (that would reorder the gradebook) and don't assign a new list to the name scores (the caller would never see it).

C4 · drop_lowest returns the removed score

The instructor wants to know which score was dropped. Return the removed value.

C5 · same_list tests object identity

== returns True for two different lists with the same contents (structural equivalence). Python has a separate operator that is True only when both operands are the exact same object.

C6 · EXTRA_CREDIT is a one-element tuple

(4) is the integer 4 with parentheses around it, so quiz_number in EXTRA_CREDIT fails. A tuple of one element needs a comma after the element, inside the parentheses.

Reflection: questions and model answers

  1. names and quiz are parallel lists. Describe concretely what the instructor would have seen if median had sorted the caller's list (use the students in the test program). Which line of your solution prevents it?

    The scores would be reordered to 61, 73, 79, 88, 95, 100 while the names stayed in place, so Ana would show 61 instead of 88 and Ben 73 instead of 61: every student gets someone else's grade, with no error message. The line that builds a new list, ordered = list(scores), prevents it because the sort then changes only the copy.

  2. In median you avoided changing the caller's list; in drop_lowest you changed it on purpose. How should a programmer decide which one a function does, and how do the people who call the function find out?

    It depends on the function's job. A function that only computes an answer (a median) should have no side effects, so callers can trust their data afterwards. A function whose job is to update the data (drop a score) must mutate the list it receives. Either way the docstring should say so, as these do: 'must keep its order' and 'remove ... from the caller's list'.

  3. Before the drop, backup == quiz was True but same_list(quiz, backup) was False. Explain the difference in your own words, and say which of the two tells you whether changing one list will change the other.

    == compares contents position by position (structural equivalence): the two lists held the same numbers. is compares identity: backup was built by list(quiz), so it is a different object. Only identity tells you about side effects: shortcut is quiz, so the drop showed up in shortcut, while backup kept all six scores.
