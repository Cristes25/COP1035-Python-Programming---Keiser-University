Cleaning up upload names

Objectives

  • Call string methods with dot notation and chain them, knowing each returns a new string
  • Get a file's extension of any length with split('.')[-1], and handle a name with no dot
  • Count words with split(), and explain why split(" ") miscounts

Requirements

  1. R1 clean_name(raw) removes spaces at both ends, converts to lowercase and replaces each remaining space with _ (" Lab 4 Strings.PY " gives "lab_4_strings.py").
  2. R2 extension(filename) returns the text after the last dot, in lowercase, whatever its length ("notes.final.TXT" gives "txt", "index.html" gives "html"), or "" when there is no dot.
  3. R3 count_words(text) returns the number of words, even when words are separated by several spaces or by line breaks.
  4. R4 Every upload in the test program is cleaned and sorted correctly. (verified by the program output)

Before you code: warm-up and model answers

  1. With the starter, what do extension("lab4.py") and extension("index.html") return? Which accepted file does is_accepted wrongly reject?

    They return '.py' and 'tml'. '.py' is not in ACCEPTED (which holds 'py'), so a real Python file, lab4.py, is rejected; the slice only works for three-letter extensions.

  2. The given is_accepted calls extension(clean_name(filename)). Why clean the name first?

    Uploads can have trailing spaces and capital letters, such as ' Lab 4 Strings.PY '. Cleaning first removes the space after the extension and makes it lowercase, so it can be compared with 'py' in ACCEPTED.

Solution

submissions.py
"""submissions.py - tidies uploaded file names and reflections for grading."""

ACCEPTED = ["py", "txt"]


def clean_name(raw):
    """Return raw without outer spaces, in lowercase, with inner spaces as underscores."""
    return raw.strip().lower().replace(" ", "_")


def extension(filename):
    """Return the lowercase extension after the last dot, or "" if there is none."""
    if "." not in filename:
        return ""
    return filename.split(".")[-1].lower()


def count_words(text):
    """Return the number of words in text."""
    return len(text.split())


def is_accepted(filename):
    """Given: True if the upload is a type the assignment accepts."""
    return extension(clean_name(filename)) in ACCEPTED

Walkthrough

Strings are immutable, so each method returns a new string and the calls chain from left to right. strip() must run before replace, or the outer spaces become underscores. split(".")[-1] is the last piece whatever its length, which is the textbook's general rule for extensions; the in test first handles names with no dot (otherwise "README" would come back as its own extension). split() with no argument treats any run of spaces, tabs and newlines as one separator; split(" ") produces an empty word for each extra space.

Messages students see when a check fails

C1 · clean_name strips the outer spaces

Call strip() to remove the spaces (and tabs or newlines) at both ends. Do it before replacing spaces, or the outer spaces turn into underscores.

C2 · clean_name converts to lowercase

Use lower() so Strings.PY and strings.py become the same name.

C3 · clean_name replaces inner spaces

Turn each remaining space into _ with replace(old, new) (or join the words from split() with "_").

C4 · extension takes the piece after the last dot

filename[-3:] assumes every extension has three letters: it gives .py for lab4.py and tml for index.html. Split on the dot and take the last piece with [-1], which works for any length and for names with several dots.

C5 · extension handles a name with no dot

"README".split(".") gives ["README"], so [-1] would return the whole name as its "extension". Test whether the name contains a dot first, and return "" if it doesn't.

C6 · extension returns lowercase

notes.final.TXT must give txt, so call lower() on the extension you return.

C7 · count_words splits on any whitespace

split(" ") makes an empty word for every extra space and keeps the line break inside a word. split() with no argument treats any run of spaces, tabs and newlines as one separator.

Progressive hints

  1. Each method returns a new string, so you can chain them: the next method works on the result of the previous one. Order matters.

  2. Look at what "notes.final.TXT".split(".") gives you in the shell (or with Run). Which piece is the extension? Then try "README".

  3. Compare "a b".split(" ") and "a b".split() with Run. Only one of them gives two words.

Reflection: questions and model answers

  1. Why does split(".")[-1] work for .py, .txt and .html, when a slice such as [-3:] doesn't? What does the [-1] refer to?

    split('.') cuts the name at every dot and returns a list of the pieces; the extension is always the last piece whatever its length, and [-1] means the last element of that list, the same negative indexing used on strings. A fixed slice assumes a length, which is wrong for py (2) or html (4).

  2. For the same reflection, split() and split(" ") give different counts. Which is right, and what exactly goes wrong with the other?

    split() is right. split(' ') splits at every single space, so two spaces in a row produce an empty string counted as a word, and a newline is not a separator, so 'me.\nNegative' counts as one word. split() treats any run of whitespace as one separator and ignores it at the ends.
