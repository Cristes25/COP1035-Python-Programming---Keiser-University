A quiz score log that survives

Objectives

  • Write numbers to a text file, converting them to strings and separating them with newlines
  • Read numbers back from a file where they are separated by spaces and/or newlines
  • Choose the right file mode ('w', 'r', 'a') and check that a file exists before reading it

Requirements

  1. R1 save_scores(filename, scores) writes each score on its own line (replacing anything already in the file) and closes the file.
  2. R2 average_score(filename) reads every score, whether separated by spaces or newlines, converts each one to a number and returns the average rounded to 1 decimal.
  3. R3 average_score returns None when the file does not exist (check with os.path.exists before opening) or holds no scores.
  4. R4 add_score(filename, score) adds one score at the end of the file without erasing the scores already there.
  5. R5 The test program's files are written, extended and summarised correctly. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter opens the file in save_scores with 'w'. If quiz1.txt already holds ten scores and you call save_scores("quiz1.txt", [88]), what will the file contain afterward? Why is that the right behaviour for this function?

    Only 88. Opening an existing file with 'w' erases its contents. That is what save_scores promises (replace the file with this list), but it would be wrong for adding a single score.

  2. Why would f.write(88) fail, and what does f.write("88") leave out?

    write only accepts a string, so passing the int 88 raises a TypeError. f.write("88") works but adds no newline, so the next score would be written on the same line: 8892.

Solution

score_log.py
"""score_log.py - keeps quiz scores in a text file, one per line."""
import os


def save_scores(filename, scores):
    """Write each score on its own line, replacing anything already in the file."""
    f = open(filename, 'w')
    for score in scores:
        f.write(str(score) + '\n')
    f.close()


def average_score(filename):
    """Return the average of the scores in the file, rounded to 1 decimal.

    Returns None if the file does not exist or contains no scores.
    """
    if not os.path.exists(filename):
        return None
    f = open(filename, 'r')
    total = 0
    count = 0
    for line in f:
        for word in line.split():
            total += int(word)
            count += 1
    f.close()
    if count == 0:
        return None
    return round(total / count, 1)


def add_score(filename, score):
    """Add one score at the end of the file, keeping the scores already there."""
    f = open(filename, 'a')
    f.write(str(score) + '\n')
    f.close()


def summary(filename):
    """Given: a one-line report built from average_score."""
    average = average_score(filename)
    if average is None:
        return filename + ": no scores yet"
    return filename + ": average " + str(average)

Walkthrough

write takes one string and adds no newline, so each score becomes str(score) + '\n'. Reading uses two loops: the for over the file gives lines, and split() breaks each line into the score strings; it also drops the newline and returns nothing for a blank line, so no strip() is needed. Mode 'a' (append) keeps the existing contents; 'w' would erase them. with open(filename, 'a') as f: is an equally good form that closes the file automatically.

Messages students see when a check fails

C1 · save_scores writes each score as a string

write only accepts a string, so convert each score with str(score) and add '\n' yourself: write does not start a new line.

C2 · save_scores closes the file

Call f.close() after the loop (or open the file with with). Output is buffered: without closing, the last chunk of data may never reach the disk.

C3 · average_score splits each line into scores

A line such as 90 85 77 holds three scores. Use line.split() and loop over the pieces; split() also discards the newline and returns nothing for a blank line.

C4 · average_score converts the strings to numbers

Everything read from a text file is a string. Convert each piece with int(...) before adding it to the total.

C5 · average_score checks that the file exists

Opening a missing file for reading crashes the program. Check os.path.exists(filename) first and return None if it is False.

C6 · add_score opens the file in append mode

Opening with 'w' erases the file, so all earlier scores would be lost. Table 4-3 lists a mode that writes after the existing contents instead. Then write the score as a string with a newline and close the file.

Progressive hints

  1. write has two demands: a string argument, and you supply the '\n' yourself.

  2. Use two loops: one for over the file object gives you lines; a second for over line.split() gives you the score strings on that line.

  3. Table 4-3 lists the file modes. One of them adds to the end of the file instead of starting it over.

Reflection: questions and model answers

  1. average_score uses line.split(), while the textbook's first example uses line.strip() and then int(line). Which file would break the strip() version, and why?

    quiz2.txt breaks it. strip() only removes whitespace at the ends, so '90 85 77' stays one string and int('90 85 77') raises ValueError, and the blank line becomes '' which int() also rejects. split() separates the scores and returns an empty list for a blank line.

  2. Why check os.path.exists before opening, instead of letting open fail? Who benefits?

    A missing file is a normal situation here (no scores recorded yet), not a bug. Checking first lets the function return None so summary prints a clear message instead of the program crashing with a FileNotFoundError traceback the TA can't act on. The textbook calls this error recovery.
