Caesar cipher clues

Objectives

  • Turn characters into numbers and back with ord and chr
  • Wrap around the end of the alphabet so x, y and z encrypt correctly
  • Decide which characters to encrypt and which to copy unchanged, and explain what that reveals

Requirements

  1. R1 encrypt(text, distance) shifts each lowercase letter distance places to the right, wrapping from z back to a ("invaders", 3 gives "lqydghuv"; "xyz", 3 gives "abc").
  2. R2 Any character that is not a lowercase letter is copied unchanged ("Gate B", 1 gives "Gbuf B").
  3. R3 decrypt(text, distance) undoes encrypt, wrapping from a back to z.
  4. R4 Decrypting an encrypted clue gives back the original for every distance from 0 to 26. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter has no wraparound. What does the starter's encrypt("zoo", 3) return? (Hint: ord('z') is 122 and chr(125) is }.)

    It returns '}rr'. The z becomes 122 + 3 = 125, which is '}' rather than 'c', while each o (111) correctly becomes r (114). Without wraparound, letters near the end of the alphabet are shifted into punctuation.

Solution

caesar.py
"""caesar.py - Caesar cipher for the Cybersecurity Club's clues."""

ALPHABET_SIZE = 26


def encrypt(text, distance):
    """Return text with each lowercase letter shifted distance places to the right."""
    code = ""
    for ch in text:
        if 'a' <= ch <= 'z':
            offset = ord(ch) - ord('a')
            cipher_value = ord('a') + (offset + distance) % ALPHABET_SIZE
            code += chr(cipher_value)
        else:
            code += ch
    return code


def decrypt(text, distance):
    """Return the original text from a clue made by encrypt(text, distance)."""
    return encrypt(text, -distance)

Walkthrough

Working with the letter's offset from 'a' (0 to 25) turns wraparound into arithmetic: % 26 keeps any shifted offset in 0..25. Python's % also gives a non-negative remainder for a negative number (-1 % 26 is 25), so decrypting is just encrypting by -distance. The textbook's version, with an if cipherValue > ord('z') correction in encrypt and a mirror-image decrypt, is equally correct.

Messages students see when a check fails

C1 · encrypt wraps past z

A shifted value beyond ord('z') has to start again at 'a'. Either subtract 26 when it goes past z (the textbook's if), or work with the offset from 'a' and take % 26.

Hint:

ord('z') is 122. With distance 3, x (120) must become a (97), not 123.

C2 · encrypt only shifts lowercase letters

Decide for each character: if it is a lowercase letter, shift it; else add it to the result unchanged. Test the character itself (for example 'a' <= ch <= 'z' or ch.islower()), before shifting it.

Hint:

ch.isalpha() is too broad: it is also true for capital letters, which must stay as they are.

C3 · decrypt shifts letters back

decrypt must move each letter distance places to the left, wrapping from a to z. Write it like encrypt with a subtraction, or reuse encrypt with a distance that undoes the shift.

Progressive hints

  1. Think of each letter as its offset from 'a': a is 0, z is 25. Wraparound is then arithmetic on numbers from 0 to 25.

  2. The remainder operator keeps a number inside 0..25 after you add the distance, and in Python it gives a non-negative answer even when the number is negative.

  3. Shifting left by d is the same as shifting right by -d (or by 26 - d). Could decrypt be one line?

Reflection: questions and model answers

  1. A clue arrives encrypted with an unknown distance. Describe how a program could find the message, and why that makes the Caesar cipher weak.

    Try every distance from 0 to 25 with decrypt and look for the one that produces readable English. There are only 26 possible keys, so a computer checks them all instantly; the key space is far too small to protect anything.

  2. Your cipher copies spaces and punctuation unchanged. What does that reveal to someone who intercepts the clue?

    They can see how many words there are, how long each one is, and where sentences and commas fall. Short words like 'a', 'at' or 'the' are easy to guess, and each guess reveals the distance. The cipher text keeps the structure of the plaintext, which is the weakness the textbook points out.

Extension

Write crack(cipher_text) that prints all 26 possible decryptions, each with its distance, so a human can spot the readable one. Run it on encrypt("capture the flag", 11).
