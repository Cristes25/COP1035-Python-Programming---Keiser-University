A base converter for the network lab

Objectives

  • Convert a string of digits in base 2, 8 or 16 to a decimal integer using positional values
  • Convert a decimal integer to any of those bases by repeated division
  • Use a string as a lookup table to turn a value into a digit, including A-F

Requirements

  1. R1 to_decimal(digits, base) returns the integer a digit string represents, by adding each digit's value times its positional value ("1100111", 2 gives 103; "19F", 16 gives 415). No int(text, base).
  2. R2 from_decimal(number, base) returns the digit string for a non-negative integer by repeated division (415, 16 gives "19F"). No bin, oct, hex or format.
  3. R3 from_decimal(0, base) returns "0".
  4. R4 Both functions agree with Python's built-ins for every number from 0 to 299 in bases 2, 8 and 16. (verified by the program output)

Before you code: warm-up and model answers

  1. In the base-8 number 637, what is the positional value of the digit 6, and what decimal number does 637 (base 8) represent?

    The 6 is in position 2, so its positional value is 8 squared, 64. The number is 6*64 + 3*8 + 7*1 = 384 + 24 + 7 = 415.

  2. The given digit_value uses DIGITS.find(ch.upper()). What does it return for 'c', and why does it call upper() first?

    It returns 12: 'c' becomes 'C', which is at position 12 in DIGITS. DIGITS only holds capital letters, so upper() lets lowercase hex digits such as 'ff' work too.

Solution

bases.py
"""bases.py - converts between decimal and bases 2 to 16 for the network lab."""

DIGITS = "0123456789ABCDEF"


def digit_value(ch):
    """Given: the value of one digit character, e.g. '7' -> 7, 'F' or 'f' -> 15."""
    return DIGITS.find(ch.upper())


def to_decimal(digits, base):
    """Return the int that the string digits represents in base (2 to 16)."""
    decimal = 0
    exponent = len(digits) - 1
    for ch in digits:
        decimal += digit_value(ch) * base ** exponent
        exponent -= 1
    return decimal


def from_decimal(number, base):
    """Return the digit string that represents number (0 or more) in base (2 to 16)."""
    if number == 0:
        return "0"
    result = ""
    while number > 0:
        remainder = number % base
        number = number // base
        result = DIGITS[remainder] + result
    return result

Walkthrough

This is the textbook's binary algorithm with the base as a parameter. The leftmost digit has exponent len(digits) - 1, and the exponent drops by one per digit. Another correct form needs no exponent: decimal = decimal * base + digit_value(ch) (Horner's method). In from_decimal the remainders come out right to left, so each new digit goes in front. DIGITS[remainder] turns 15 into F; str(15) would add two characters, 15.

Messages students see when a check fails

C1 · to_decimal uses positional values

Multiply each digit's value by base ** exponent, where the leftmost digit's exponent is len(digits) - 1, and add the results. Don't call int(text, base): the point is to do the conversion yourself.

C2 · to_decimal gets each digit's value with digit_value

int(ch) works for 0-9 but crashes on F. Use the given digit_value(ch), which looks the character up in DIGITS.

C3 · from_decimal divides repeatedly by the base

In a loop, number % base gives the next digit (from the right) and number // base gives what's left to convert. Keep going while number > 0. Built-ins such as bin, hex or format skip the algorithm.

C4 · from_decimal looks digits up in DIGITS and puts them in front

Turn each remainder into a digit with DIGITS[remainder] (so 15 becomes F), and place it in front of the digits found so far: the remainders come out right to left.

C5 · from_decimal handles 0

while number > 0 never runs when number is 0, so the result would be an empty string. Check for 0 before the loop and return "0".

Progressive hints

  1. For "637" in base 8 the positional values, from the left, are 8 squared, 8 to the 1st and 8 to the 0th power. Start the exponent at len(digits) - 1 and count down.

  2. Division gives you the digits from the right, the same way as the textbook's decimaltobinary.py. Each new digit belongs at the front of the string you have so far.

  3. A loop that runs while number > 0 does nothing for 0. Handle it before the loop.

Reflection: questions and model answers

  1. from_decimal uses DIGITS[remainder] instead of str(remainder). What would the str version return for 415 in base 16, and why is that wrong?

    The remainders are 15, 9 and 1, so the str version builds '1' + '9' + '15' = '1915'. A digit must be a single character; '15' takes two places and makes the number unreadable (it looks like four hex digits). DIGITS[15] is the single digit 'F', giving '19F'.

  2. Why does each hexadecimal digit correspond to exactly four binary digits? Use that to convert C0 to binary without your program.

    16 is 2 to the 4th power, so the 16 possible hex digits match the 16 patterns of four bits exactly. C is 12, which is 1100, and 0 is 0000, so C0 is 11000000, which is the octet 192.
