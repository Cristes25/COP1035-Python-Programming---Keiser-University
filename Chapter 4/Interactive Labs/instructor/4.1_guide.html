COP1035 · Python Programming · Lab 4.1

Reading a section code

Objectives

  • Use the subscript operator s[i] to read one character, and convert it with int
  • Extract substrings with slices, counting from the left or from the right end
  • Test for a substring with the in operator, choosing a target that can't match by accident

Requirements

  1. R1 prefix(code) returns the three-letter prefix (COP) and course_number(code) the four digits (1035), using slices.
  2. R2 level(code) returns the first digit of the course number as an int (COP1035-02 gives 1).
  3. R3 section(code) returns the two-digit section for regular and lab codes alike (COP1035-02 gives 02, COP1035L-01 gives 01).
  4. R4 is_lab(code) returns True only for lab sections; LIT2000-01 is not a lab.
  5. R5 Every code in the test program is described correctly. (verified by the program output)

Before you code: warm-up and model answers

  1. Before changing anything: the starter's section returns code[8:10]. What does it return for COP1035-02, and for COP1035L-01? Why does one of them go wrong?

    It returns '02' for COP1035-02 but '-0' for COP1035L-01. The L takes position 7, so the hyphen and section digits each move one position right; fixed positions from the left break when the length changes.

  2. What is len("COP1035L-01"), and what is the position of its last character?

    The length is 11, so the last character is at position 10 (length minus 1), which Python also lets you write as -1.

Solution

course_codes.py
"""course_codes.py - pulls apart section codes such as COP1035-02 and COP1035L-01."""


def prefix(code):
    """Return the three-letter subject prefix, e.g. 'COP'."""
    return code[:3]


def course_number(code):
    """Return the four-digit course number as a string, e.g. '1035'."""
    return code[3:7]


def level(code):
    """Return the course level as an int, e.g. 1 for COP1035."""
    return int(code[3])


def section(code):
    """Return the two-digit section, e.g. '02'."""
    return code[-2:]


def is_lab(code):
    """Return True if the code is a lab section."""
    return "L-" in code


def describe(code):
    """Given: builds a one-line label from the functions above."""
    label = prefix(code) + " " + course_number(code) + ", section " + section(code)
    if is_lab(code):
        label += " (lab)"
    return label

Walkthrough

The prefix and number sit at fixed positions from the left, so positive slices are right for them. The section is fixed from the right end, so code[-2:] works whether or not an L pushes it along. "L-" in code looks for the two characters that only lab codes have together; "L" in code would also match prefixes such as LIT or MLS. code[7] == "L" is also correct.

Messages students see when a check fails

C1 · prefix slices the first three characters

Take a slice that starts at the beginning and stops before position 3. The second number in a slice is where it stops, and that position is not included.

Hint:

Positions 0, 1 and 2 hold the prefix.

C2 · course_number slices positions 3 to 6

The four digits occupy positions 3, 4, 5 and 6. A slice stops before its second number, so which number must end it?

C3 · level converts one character to an int

Read the single character where the course number starts with the subscript operator, then pass it to int(...). That character is the string '1'; the dashboard needs the number 1.

C4 · section counts from the right end

code[8:10] breaks on lab codes: the L moves the section one position right. The section is always the last two characters, so count from the right end: a negative start position does that.

C5 · is_lab searches for a target only lab codes contain

Use in with a target that only lab codes contain. Searching for just "L" says LIT2000-01 is a lab, because L is also in the prefix. What comes right after the L in a lab code?

Progressive hints

  1. Write a code's positions on paper first. A slice s[a:b] takes positions a up to, but not including, b.

  2. For the section, count from the right: -1 is the last character, -2 the one before it. Negative positions don't move when an L appears in the middle.

  3. "L" in code is too eager: the prefix can contain an L. In a lab code the L is always followed by one particular character.

Reflection: questions and model answers

  1. Why is code[-2:] a better choice than code[8:10] for the section, even if every code were a regular section today?

    The section is defined by where it sits relative to the end of the code, not the start. Counting from the right keeps working when something is added in the middle (a lab L, a longer course number), so the function doesn't silently return the wrong text when the format grows.

  2. Give a code that would fool "L" in code, and explain how searching for "L-" avoids it.

    LIT2000-01 (or any prefix with an L) contains an L but is not a lab. In a valid code the hyphen comes only after the number, so the two characters L- appear together only when the lab L is present; the longer target can't match by accident in the prefix.
