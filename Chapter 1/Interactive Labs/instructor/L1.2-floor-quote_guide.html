Floor-area quote

Objectives

  • Organise a script as input, processing and output, the shape of most useful programs (section 1.4)
  • Choose float() instead of int() when the input can contain a decimal point
  • Control how print separates and ends its output with commas and end=""

Requirements

  1. R1 width, length and price are converted with float(), so answers like 12.5 and 3.50 are accepted (no int() in the script).
  2. R2 area is width times length, and cost is area times price, both computed from the variables.
  3. R3 The area line ends with square feet, and the cost line shows the amount right after $, with no space.
  4. R4 The output matches the brief exactly for every customer. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter already prints the Room line. Run it with 12.5, 10 and 3.50. Why does it show 10 and not 10.0, as the brief does?

    Because length is still the string the customer typed, "10", and print shows a string exactly as it is. Only after converting it with float() does length become the number 10.0, which print shows with a decimal point.

  2. The starter's last line prints Estimated cost: $ 0. Where does the space after $ come from?

    print puts a single space between the values it is given, so separating the text "Estimated cost: $" and cost with a comma adds a space between them. Removing it needs a different way of ending or separating the output, not a change to the text.

Solution

floor_quote.py
# floor_quote.py - vinyl-plank quote for one rectangular room

# Input
width = float(input("Room width in feet: "))
length = float(input("Room length in feet: "))
price = float(input("Price per square foot: "))

# Processing
area = width * length
cost = area * price

# Output
print("Room:", width, "x", length, "feet")
print("Area:", area, "square feet")
print("Estimated cost: $", end="")
print(cost)

Walkthrough

float() accepts both 12.5 and 10; int("12.5") would stop the script with a ValueError. Once length is a float, print shows it as 10.0, which is why the brief's Room line reads 10.0. print separates values with one space, so the cost line needs two print calls: the first ends with end="" instead of a newline, and the second prints the amount on the same line. An equally correct alternative is one call with sep="": print("Estimated cost: $", cost, sep="").

Messages students see when a check fails

C1 · All three answers become floats

Each of width, length and price needs float(...): until then they are strings and cannot be multiplied. Use float, not int, because a customer may type 12.5.

C2 · No int() for measurements or prices

Use float() for every value in this script, never int(): int("12.5") stops the script with a ValueError, because text with a decimal point is not an integer.

C3 · area is width times length

The floor of a rectangular room is width times length. Compute area from the two variables with *.

C4 · cost is area times price

The customer pays price dollars for every square foot, so cost is area * price. Reuse area instead of measuring again.

C5 · The area line says square feet

A bare number is not a quote: add the text "square feet" after area in the same print call, so the line reads Area: 125.0 square feet.

C6 · No space after the dollar sign

print always puts a space between values, which leaves $ 437.5. End the first part with end="" (so the next print continues on the same line), or set sep="".

Hint:

Section 1.4: print(<expression>, end = "") says "end the line with an empty string instead of a newline".

Progressive hints

  1. Start with the input: run the starter, then convert one value at a time and watch the Room line change.

  2. Processing is two lines of arithmetic. In Python, * multiplies; the second line can use the result of the first.

  3. For the cost line, think of it as two prints: the label, then the amount. The first one must not move to a new line.

Reflection: questions and model answers

  1. What would happen if your script used int() and a customer typed 12.5? Why is float() the better choice even for a customer who types a whole number like 10?

    int("12.5") raises a ValueError and the script stops before any quote is printed. float() accepts both kinds of input: "12.5" becomes 12.5 and "10" becomes 10.0, so one conversion handles every measurement a customer can give.

  2. Section 1.4 says most useful programs accept inputs, process them, and output results. Point to each part in your script, and explain why the processing has to come after the conversion with float().

    The three input lines are the input, the two arithmetic lines are the processing, and the print lines are the output. The processing must come after float(), because before conversion the values are strings, and multiplying two strings is an error in Python.
