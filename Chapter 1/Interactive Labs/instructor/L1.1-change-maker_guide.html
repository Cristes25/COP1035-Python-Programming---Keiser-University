Change maker

Objectives

  • Turn the four steps of the book's making-change algorithm into four parts of a Python script
  • Convert keyboard input from a string to an integer with int() before doing arithmetic
  • Print text and a computed value on one line with print(..., ..., ...)

Requirements

  1. R1 Both answers, price and paid, are converted from strings to integers with int().
  2. R2 change is the amount paid minus the price, computed from the two variables (never typed in as a number).
  3. R3 The script prints exactly one result line in this form: Change due: 761 cents.
  4. R4 The same script gives the right change for every sale, including an exact payment (0 cents). (verified by the program output)

Before you code: warm-up and model answers

  1. Suppose you only changed Step 3 to change = paid - price and left the two input lines as they are. You run it and type 239 and 1000. What happens, and why?

    The script stops with a TypeError (unsupported operand type(s) for -: 'str' and 'str'). input() always returns a string, so price is the text "239" and paid is the text "1000". Python cannot subtract one piece of text from another; the strings must be converted to numbers with int() first.

  2. Match each of the four algorithm steps in the comments to the lines of code below them. Which step is the processing, and which are input and output?

    Steps 1 and 2 are input (the two input() lines), Step 3 is processing (the line that computes change), and Step 4 is output (the print line). The script is the algorithm, written in a language the computer can run.

Solution

change_maker.py
# change_maker.py - change for the Saturday farmers' market stall
#
# The algorithm (Section 1.1):
#   Step 1  Get the purchase price.
#   Step 2  Get the amount the customer hands over.
#   Step 3  Change = amount paid - purchase price.
#   Step 4  Tell the cashier how much change to give back.
#
# Money is typed in cents (a dozen eggs at $2.39 is 239), so every
# value is a whole number.

# Steps 1 and 2: input
price = int(input("Price in cents: "))
paid = int(input("Amount paid in cents: "))

# Step 3: processing
change = paid - price

# Step 4: output
print("Change due:", change, "cents")

Walkthrough

int(input(...)) converts each answer the moment it arrives, so price and paid are numbers for the rest of the script. The order paid - price matters: the other way round gives -761. Passing three values to print separated by commas makes Python put one space between them, which is exactly the format the cashier sees. Nothing in the script mentions 761, so it solves the whole class of problems (section 1.1, feature 4), not one example.

Messages students see when a check fails

C1 · price becomes an integer

price is still the text the cashier typed. Wrap the input in int(...) so it becomes a number you can subtract: input() always returns a string.

Hint:

The book's example: first = int(input("Enter the first number: ")).

C2 · paid becomes an integer

paid is still a string. Convert it with int(...) the same way as price; both values must be numbers before Step 3 can subtract them.

C3 · change is computed as paid minus price

Step 3 says change = amount paid - purchase price. Compute change from the two variables in that order: price - paid would tell the cashier to give back -761 cents.

C4 · No answer typed in by hand

change must be calculated from paid and price, never set to a number such as 0 or 761. An algorithm solves a general class of problems (section 1.1): a typed-in answer is right for one sale only.

C5 · The result line prints the variable change

The output line prints only the label. Pass change to the same print call, separated by commas from the text, so the cashier sees the number: print puts one space between the values.

C6 · The result line ends with the word cents

The cashier must know the unit: after change, add the text "cents" as one more value in the same print call, so the line reads Change due: 761 cents.

Progressive hints

  1. Work through the algorithm one step at a time, top to bottom. Run after each change and type 239 and 1000 in Program input.

  2. Steps 1 and 2 already ask the questions. What they give back is text; the book's sum example (Table 1-2) shows how to turn text into a whole number in the same line.

  3. print accepts several values separated by commas and puts a single space between them. The label, the variable and the word cents are three values.

Reflection: questions and model answers

  1. Your script gave the right change for three different sales without being edited. Which feature of an algorithm from section 1.1 does that show, and why would a script that simply printed Change due: 761 cents not be an algorithm for making change?

    It shows that an algorithm solves a general class of problems: the same steps work for any price and any amount paid. A script that prints 761 solves only one sale (the eggs); for any other purchase the answer would be wrong, so it does not describe a process for making change at all.

  2. When the volunteer uses your script on the stall's laptop, which hardware from section 1.2 handles the input, the processing and the output?

    The keyboard is the input device that delivers the typed amounts; the values are stored in memory as binary; the CPU fetches and executes the subtraction (the processing); and the monitor is the output device that shows the Change due line in a form a person can read.
