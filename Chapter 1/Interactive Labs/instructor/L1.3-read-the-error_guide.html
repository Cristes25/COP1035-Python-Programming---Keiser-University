Read the error

Objectives

  • Read a Python error message: the kind of error, the line, and what Python could not do
  • Fix the syntax errors the book describes: an unexpected indent and an incomplete expression
  • Explain why a syntax error stops a script before any line runs, while a misspelled name fails only when its line is reached

Requirements

  1. R1 The script passes the syntax check: no line starts with unexpected spaces, and no expression is missing an operand.
  2. R2 Every variable is used with exactly the name it was given, and remaining is the goal minus the hours logged.
  3. R3 The fixed script prints the report shown in the brief for any week's answers. (verified by the program output)

Before you code: warm-up and model answers

  1. Jordan's script starts with print("Weekly study log"). Before you press Run: will that line appear in the output? Explain using what the interpreter does before the Python virtual machine runs anything.

    No. The interpreter first checks the syntax of the whole script and translates it to byte code. It finds the unexpected indent on line 7 and halts with an error message before any byte code reaches the PVM, so not even the first print runs.

  2. Read the starter without running it. Find the three mistakes. Which two can Python report before running anything, and which one can it only discover while the program is running?

    The indented goal line and the incomplete expression goal - are syntax errors, found during the syntax check. The misspelled cours is grammatically fine, so Python only discovers it is undefined when the PVM executes that line, after the title has printed and the inputs were typed.

Solution

study_log.py
# study_log.py - weekly study-hours log, written by your classmate Jordan
# Jordan: "It won't even start and I don't know why. Can you fix it?"

print("Weekly study log")
course = input("Course: ")
hours = int(input("Hours studied: "))
goal = int(input("Goal: "))
remaining = goal - hours  # hours still needed to reach the goal
print("Course:", course)
print("Hours logged:", hours)
print("Hours to goal:", remaining)

Walkthrough

Three mistakes, found in this order. (1) Line 7 starts with two spaces: IndentationError: unexpected indent. (2) Line 8, goal -, is missing its second operand, like the book's 3 +: SyntaxError: invalid syntax. Both are found by the syntax checker before any byte code runs, so the starter prints nothing at all, not even Weekly study log. (3) Once the script translates, it runs: it prints the title, asks all three questions, and only then stops with NameError at cours, because a misspelled name is discovered by the PVM when that line executes. Current Python even adds Did you mean: 'course'?, but it never runs a guess.

Messages students see when a check fails

C1 · No line starts with unexpected spaces

A line still begins with spaces. Indentation is significant in Python: outside control statements and definitions, every line must start in the leftmost column (section 1.4). Delete the spaces before the first word.

C2 · No expression is missing an operand

A line ends with an operator and nothing after it, like the book's 3 +. The syntax checker rejects it as invalid syntax. Give the operator its second operand.

C3 · remaining is goal minus hours

remaining should hold the hours still needed: the weekly goal minus the hours already logged. Read the comment on that line: it says what Jordan meant.

C4 · The course is printed with its real name

The script uses a name that was never given a value. Python reads only what you type, not what you meant: use exactly the name created by the input line.

Progressive hints

  1. Press Run before changing anything and read the last line of the error first: it names the kind of error. The line above it points to where Python stopped.

  2. Fix one error, then run again. A syntax error hides everything after it, so expect a new message after each fix. When the title finally prints, you have moved from the syntax checker to the PVM.

  3. One mistake is invisible at a glance: look at the very start of each line. Another is a subtraction with nothing to subtract. The last one is a single missing letter.

Reflection: questions and model answers

  1. With the two syntax errors fixed but cours still there, the script printed Weekly study log and asked all three questions before it stopped. Why did this error wait until then, while the syntax errors stopped everything at once?

    Syntax errors are found when the interpreter checks and translates the whole script, before the PVM executes any byte code, so nothing runs. cours is valid grammar; it only fails when the PVM reaches that line and finds the name has no value, so every line before it has already run.

  2. Current versions of Python add Did you mean: 'course'? to the NameError, yet still stop instead of using course. Why is stopping better than running a guess?

    A guess could be wrong and the program would continue with the wrong value, producing output that looks right but isn't, which is much harder to notice than an error. Stopping makes the mistake visible at the exact line and leaves the decision to the programmer, who knows what was intended.
