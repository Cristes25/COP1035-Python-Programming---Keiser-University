COP1035 · Python Programming · Lab L2.2-event-badge

Event check-in badge

Objectives

  • Build new strings with concatenation (+) and repetition (*)
  • Use escape sequences (\t, \") and quotation marks to control exactly what prints
  • Choose variable and constant names that explain their purpose

Requirements

  1. R1 Build the border from the constants with repetition, BORDER * BADGE_WIDTH, instead of typing stars.
  2. R2 Build fullName by concatenating the first name, one space and the last name.
  3. R3 Indent the name line with the tab escape sequence \t.
  4. R4 Print the event name inside double quotation marks: Event: "Python Night".
  5. R5 Print the reminder Don't forget your laptop! with its apostrophe.
  6. R6 The badge matches the example line for line, for every guest. (verified by the program output)

Before you code: warm-up and model answers

  1. Read the starter. Exactly what does it print on the name line for Maya Ortiz, and why?

    It prints MayaOrtiz with no space. Concatenation glues strings together exactly as they are; nothing adds a space unless the program concatenates a " " string between the two names.

  2. Why can print('Don't forget your laptop!') not work, while the same text in double quotes does?

    In a single-quoted literal the apostrophe in Don't ends the string early, so Python sees Don as the string and then t forget... as broken code, a syntax error. Inside double quotes the apostrophe is just a character.

Solution

badge.py
"""
Program: badge.py
Author: (your name)
Print a name badge at the Tech Club's event check-in kiosk.
"""

BADGE_WIDTH = 30   # characters across the badge
BORDER = "*"       # character used for the top and bottom edge

firstName = input("First name: ")
lastName = input("Last name: ")
eventName = input("Event: ")

# Join the names with one space between them
fullName = firstName + " " + lastName

# Repeat the border character across the badge
border = BORDER * BADGE_WIDTH

print(border)
print("HELLO, my name is")
print("\t" + fullName)
print("Event: \"" + eventName + "\"")
print("Don't forget your laptop!")
print(border)

Walkthrough

BORDER * BADGE_WIDTH means a wider badge is a one-number change, and switching to = is a one-character change. The escaped \" puts a double quotation mark inside a double-quoted string; 'Event: "' + eventName + '"' with single-quoted literals works too. The apostrophe in Don't is safe because the literal is in double quotes.

Messages students see when a check fails

C1 · The border is built with repetition

Replace the typed stars with BORDER * BADGE_WIDTH. The * operator repeats a string a whole number of times, so the border is always exactly as wide as the constant says.

C2 · The full name has a space between the names

Concatenate a string holding one space between the names: first name, then " ", then last name. + adds nothing on its own.

C3 · The name line uses the tab escape \t

Start the name line with the escape sequence \t (a backslash then t) inside a string, for example concatenated before fullName. Typing spaces would not line up the same way on every printer.

C4 · The event name is printed inside double quotes

Print a " before and after the event name. Inside a double-quoted string write it as the escape \"; inside a single-quoted string you can type " directly.

C5 · The reminder line is printed

Add print("Don't forget your laptop!") before the bottom border. Put the text in double quotes (or escape the apostrophe as \') so the apostrophe doesn't end the string.

Progressive hints

  1. Compare the starter's output with the example badge line by line: each difference is one requirement.

  2. Escape sequences start with a backslash and live inside a string literal: one for the tab, one for each double quotation mark.

  3. The border needs no stars typed at all: the string you repeat is already stored in a constant.

Reflection: questions and model answers

  1. The constants BADGE_WIDTH and BORDER each have an end-of-line comment, but firstName does not. When is a comment worth writing, and when is it noise?

    A comment is worth it when the code alone doesn't say why a value is what it is or what it is for, such as a width measured in characters or the character used for the edge. firstName already explains itself, so a comment would repeat the code and become one more thing to keep up to date.

  2. Why is border = BORDER * BADGE_WIDTH better than typing 30 stars, even though both print the same line today?

    The expression ties the border to the constants, so changing the badge width or the border character takes one edit and can't leave the two borders different lengths. Typed stars are a hidden copy of the width that someone must remember to recount by hand.

Extension

Make the badge wider without touching any print line: change one constant, then press Run. Then try BORDER = "=-". What happens to the width, and why?
