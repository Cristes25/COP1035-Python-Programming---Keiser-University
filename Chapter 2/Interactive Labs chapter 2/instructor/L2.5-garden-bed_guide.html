Raised garden bed planner

Objectives

  • Import a module and use its resources with the qualifier: math.pi, math.ceil
  • Use a function's optional argument: round(x, 2)
  • Choose between int, round and math.ceil by what the result is for
  • Lay out a script in the standard order: docstring, imports, constants, input, processing, output

Requirements

  1. R1 Import the module with import math right after the docstring, and use math.pi (with the qualifier) instead of 3.14.
  2. R2 Display the area and the edging rounded to 2 decimal places with round's optional second argument.
  3. R3 Compute bags with math.ceil, so the club never buys too little soil.
  4. R4 Every bed in the test suite gets the right area, edging and number of bags. (verified by the program output)

Before you code: warm-up and model answers

  1. A bed needs 9.42 bags of soil. What do int(9.42) and round(9.42) give, and how many bags does the club actually need?

    Both give 9: int truncates the fraction and round goes to the nearest whole number, which is 9. The club needs 10 bags, because the 0.42 of a bag still has to be bought.

  2. round(28.274334, 2) and round(28.274334): what does each return, and what does the second argument change?

    round(28.274334, 2) returns 28.27 and round(28.274334) returns 28. The optional second argument is the number of decimal places to keep; without it round returns the nearest whole number.

Solution

garden_bed.py
"""
Program: garden_bed.py
Author: (your name)
Plan materials for a round raised garden bed.
Inputs: diameter and soil depth, in feet
Outputs: bed area, length of edging, bags of soil to buy
"""

import math

BAG_VOLUME = 1.5   # cubic feet of soil in one bag

diameter = float(input("Diameter (ft): "))
depth = float(input("Soil depth (ft): "))

radius = diameter / 2
area = math.pi * radius ** 2
edging = math.pi * diameter

# Round up: a partly used bag still has to be bought
bags = math.ceil(area * depth / BAG_VOLUME)

print("Bed area: " + str(round(area, 2)) + " sq ft")
print("Edging needed: " + str(round(edging, 2)) + " ft")
print("Soil bags to buy: " + str(bags))

Walkthrough

int truncates and round goes to the nearest whole number, so both can come out below what the bed needs (9.42 bags becomes 9). math.ceil always rounds up. Rounding happens only for display: the bag count uses the full-precision area. math.pi keeps the reader aware the value comes from the math module, which is why the qualified import is preferred over from math import *.

Messages students see when a check fails

C1 · import math comes right after the docstring

Put import math on its own line directly after the docstring, before the constants. Imports come first so a reader sees every module the script depends on; the plain import math form keeps the math. qualifier on every use.

C2 · math.pi replaces 3.14

Replace each 3.14 with math.pi. The module's value is accurate to about 16 digits; 3.14 is off by more than a twentieth of a percent, which adds up on a large bed.

C3 · Area and edging are rounded to 2 places

Show round(area, 2) and round(edging, 2) in the output lines. Round for display only, so the bag count still uses the precise area.

C4 · Bags are rounded up with math.ceil

Use math.ceil(...) for bags. int truncates and round can round down, and either one leaves the club short of soil.

Progressive hints

  1. Section 2.5 recommends importing the module name, then writing the module as a qualifier on every use.

  2. dir(math) lists a function whose name means the opposite of floor.

  3. Round inside the print lines, not where area is computed: the soil calculation needs the precise value.

Reflection: questions and model answers

  1. When is int the right tool, when is round, and when is math.ceil? Give one example from everyday life for each.

    int when the fraction should simply be dropped, like counting complete years of age. round when the nearest value is fairest, like a score of 89.6 shown as 90. math.ceil when running short is not acceptable, like buses for a field trip or bags of soil: any fraction means one more.

  2. Section 2.5 prefers import math with math.pi over from math import *. What does the qualifier buy you in a longer program?

    The qualifier tells the reader where each name comes from, and it keeps names from different modules apart: two modules can both define a function with the same name, and with import * one silently replaces the other. With math.ceil there is no doubt which function runs.
