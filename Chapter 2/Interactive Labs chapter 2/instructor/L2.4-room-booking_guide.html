COP1035 · Python Programming · Lab L2.4-room-booking

Study room booking

Objectives

  • Choose between /, // and % for the result you need
  • Write expressions whose order of evaluation is the one you intend
  • Round money with round(value, 2) and convert numbers with str() for output

Requirements

  1. R1 Split the booking into hours with // and leftover extraMinutes with %.
  2. R2 roomCost is minutes times the hourly rate divided by 60, rounded to 2 decimal places with round(..., 2).
  3. R3 share is the room cost divided by the number of people, rounded to 2 decimal places.
  4. R4 Convert every number to a string with str() before concatenating it into an output line.
  5. R5 Every case prints the expected lines, including one where floating-point arithmetic is not exact. (verified by the program output)

Before you code: warm-up and model answers

  1. For a 135-minute booking, what do 135 / 60, 135 // 60 and 135 % 60 evaluate to?

    135 / 60 is 2.25 (exact division always gives a float), 135 // 60 is 2 (the integer quotient), and 135 % 60 is 15 (the remainder).

  2. The starter's line print("Room cost: $" + roomCost) stops the program. What error is it, and why?

    A TypeError. roomCost is a float, and Python won't use + between a string and a number because it checks operand types before applying an operator. The number must be converted with str() first.

Solution

room_booking.py
"""
Program: room_booking.py
Author: (your name)
Print the time, cost and per-person share of a study room booking.
"""

MINUTES_PER_HOUR = 60

minutes = int(input("Minutes booked: "))
rate = float(input("Hourly rate: "))
people = int(input("People: "))

# Whole hours, and the minutes that don't make a full hour
hours = minutes // MINUTES_PER_HOUR
extraMinutes = minutes % MINUTES_PER_HOUR

# Cost of the booking, rounded to cents
roomCost = round(minutes * rate / MINUTES_PER_HOUR, 2)

# Each person's share, rounded to cents
share = round(roomCost / people, 2)

print("Booked time: " + str(hours) + " h " + str(extraMinutes) + " min")
print("Room cost: $" + str(roomCost))
print("Each person pays: $" + str(share))

Walkthrough

// keeps the whole hours as an int and % gives what is left; / would give 2.25, a fraction of an hour that no one reads as minutes. Multiplying before dividing (minutes * rate / 60) keeps the arithmetic exact for these inputs, and round(..., 2) cleans up cases like 50 minutes split three ways. str() is required because Python is strongly typed: "$" + 45.0 is a TypeError.

Messages students see when a check fails

C1 · hours uses integer division //

Use // for the whole hours. / always produces a float such as 2.25, which is a fraction of an hour, not a count of hours.

C2 · extraMinutes uses the remainder %

The minutes left after the whole hours are the remainder of dividing by 60: use %.

C3 · roomCost is rounded to 2 decimal places

Wrap the cost expression in round(..., 2). The second argument is optional; without it, round returns a whole number and the cents are lost.

C4 · share divides the cost by the people, rounded

Set share to round(roomCost / people, 2). Divide the rounded cost the group actually pays, not a recomputed value.

C5 · Numbers are converted with str() for output

Convert roomCost and share with str(...) before concatenating them. + between a string and a float is a TypeError.

Progressive hints

  1. Three division operators, three different answers: one for a float, one for the whole part, one for what's left.

  2. If you divide by 60 before multiplying by the rate, use parentheses or check that the order still gives the same value. Either way, round once, at the end.

  3. The crash comes from mixing types in +, not from the arithmetic.

Reflection: questions and model answers

  1. Case 2 is 125 minutes at $15.00. In algebra 125 / 60 * 15.0 and 125 * 15.0 / 60 are equal, but Python prints 31.250000000000004 for the first and 31.25 for the second. Why, and how does your program protect the receipt?

    Floats have limited precision, and 125 / 60 is a repeating fraction that can't be stored exactly, so multiplying it by 15 carries a tiny error. Multiplying first keeps the intermediate value exact here, and rounding the final amount to 2 decimals removes any leftover error before it reaches the receipt.

  2. Why does hours use // while roomCost uses /? What would go wrong if they were swapped?

    Hours are a count of whole hours, so the integer quotient is what's wanted and the rest comes from %. Cost needs the exact fraction: with // the group would only pay for full hours, so 50 minutes would cost $0 and 135 minutes would lose the 15-minute part.
