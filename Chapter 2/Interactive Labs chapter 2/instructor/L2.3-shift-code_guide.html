Escape-room shift code

Objectives

  • Use ord and chr to move between characters and their ASCII codes
  • Choose the right data type for each value: str, int
  • Reverse an encoding to prove it can be read back

Requirements

  1. R1 Store the letter's ASCII code in letterCode using ord.
  2. R2 Convert shift to an int, then build encoded with chr of the code plus the shift.
  3. R3 Build decoded from encoded itself, shifting back by the same amount, as a player would.
  4. R4 The three output lines are right for every case, including a shift that leaves the alphabet. (verified by the program output)

Before you code: warm-up and model answers

  1. Using the ASCII table in Section 2.3, what is ord('H'), and what does chr(ord('H') + 3) evaluate to?

    ord('H') is 72. Adding 3 gives 75, and chr(75) is 'K'.

  2. The starter reads shift with input() and doesn't convert it. What would ord(letter) + shift do with that value, and why?

    It raises a TypeError: ord returns an int, but shift is still a string such as '3', and Python won't add an int and a str. The shift has to be converted with int() first.

Solution

shift_code.py
"""
Program: shift_code.py
Author: (your name)
Encode one letter for the escape-room clue and check it decodes.
"""

letter = input("Letter: ")
shift = int(input("Shift: "))

# The character set maps each character to an integer code
letterCode = ord(letter)

# Move along the character set by the shift
encoded = chr(letterCode + shift)

# A player works backwards from the clue on the wall
decoded = chr(ord(encoded) - shift)

print("Code of " + letter + ": " + str(letterCode))
print("Encoded letter: " + encoded)
print("Decoded again: " + decoded)

Walkthrough

ord returns an int, so the shift must be an int too before they are added; chr then turns the new code back into a one-character string. Decoding starts from encoded, not from letter: copying letter would print the right answer without proving anything. Case 3 shows that the character set doesn't wrap: X shifted by 4 lands on the backslash.

Messages students see when a check fails

C1 · letterCode comes from ord

Set letterCode = ord(letter). ord looks up the character's integer code in the character set (72 for H).

C2 · The shift is converted to an int

Convert the shift with int(...): input() returns text, and text can't be added to the integer that ord returns.

C3 · encoded uses chr of code plus shift

Build encoded with chr(...) around the letter's code plus the shift. chr turns the shifted number back into a character.

C4 · decoded works backwards from encoded

Decode the way a player would: take the code of encoded with ord, subtract the shift, and turn it back with chr. Reusing letter or letterCode would pass without testing that the clue can be solved.

Progressive hints

  1. There are two kinds of values here: one-character strings and integer codes. ord goes one way, chr the other.

  2. Before anything is added to the code, the shift has to stop being text.

  3. Decoding is the same idea as encoding with the opposite sign, and it starts from encoded.

Reflection: questions and model answers

  1. Case 3 turned X into a backslash. Why does that happen, and why is it a problem for the escape room?

    The character set is just a numbered list, and after Z (90) come symbols like [ and \, so adding 4 to 88 gives 92, the backslash. Players expect a letter, so the clue would look broken. The program needs to wrap around from Z back to A, which needs the remainder operator from Section 2.4.

  2. Why is the decoded line computed from encoded instead of simply printing letter again?

    Printing letter would always look right, so it would prove nothing. Decoding from encoded is a real test: if the shift were applied wrongly, or the wrong sign used, the decoded letter would differ from the original and the bug would show.

Extension

Lowercase letters have their own codes. Run your program with h and 3, then z and 3. Use the results to explain why the escape room should stick to one case.
