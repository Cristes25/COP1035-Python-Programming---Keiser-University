Term cost estimator

Objectives

  • Turn an analysis and a pseudocode design into working Python
  • Name fixed values as symbolic constants instead of typing magic numbers
  • Convert typed input with int() before doing arithmetic
  • Explain why a test suite checks edge cases such as 0

Requirements

  1. R1 Name the three amounts as symbolic constants written as dollars and cents: TUITION_PER_CREDIT = 425.0, TECH_FEE = 150.0, LAB_FEE = 60.0.
  2. R2 Convert both inputs to whole numbers with int() before using them.
  3. R3 Compute termCost from the pseudocode formula using the constants only: no 425, 150 or 60 in the arithmetic.
  4. R4 Every case in the test suite prints the expected cost, for example Estimated term cost: $5370.0 for 12 credits and 2 labs. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, credits holds whatever input() returned. If you typed 12 and the program then evaluated credits * 425.0, what would happen, and why?

    Python stops with a TypeError. input() always returns a string, so credits is the text '12', not the number 12, and a string cannot be multiplied by a float. It has to be converted with int() first.

  2. Which part of the docstring is the analysis (what the program does) and which is the design (how it does it)?

    The constants, inputs and output describe what the program must do, which came from analysis. The computation step, the formula that turns inputs into the cost, is the design: it says how the program will do it.

Solution

term_cost.py
"""
Program: term_cost.py
Author: (your name)
Estimate what one term will cost a student.

1. Significant constants
   tuition per credit hour
   technology fee (once per term)
   lab fee (per lab course)
2. The inputs are
   number of credit hours
   number of lab courses
3. Computation:
   term cost = credits * tuition per credit
               + technology fee
               + lab courses * lab fee
4. The output is
   the estimated term cost
"""

# Initialize the constants
TUITION_PER_CREDIT = 425.0   # dollars per credit hour
TECH_FEE = 150.0             # charged once per term
LAB_FEE = 60.0               # charged for each lab course

# Request the inputs
credits = int(input("Credit hours: "))
labCourses = int(input("Lab courses: "))

# Compute the term cost
termCost = credits * TUITION_PER_CREDIT + TECH_FEE + \
           labCourses * LAB_FEE

# Display the term cost
print("Estimated term cost: $" + str(termCost))

Walkthrough

The constants are floats (425.0) because they are money; mixing them with the int inputs makes the result a float, so the output reads $5370.0, exactly like the tax calculator's $26200.0. Converting with int() right where the input is read means every later line can trust that credits is a number. Because the fees live in one place, next year's price change is a one-line edit: that is what cheaper maintenance looks like.

Messages students see when a check fails

C1 · The three amounts are named constants

Define TUITION_PER_CREDIT = 425.0, TECH_FEE = 150.0 and LAB_FEE = 60.0 under the "Initialize the constants" comment. Write each with a decimal point: they are dollar amounts, and the float makes the output show cents ($5370.0).

Hint:

Uppercase names tell every reader "this value never changes while the program runs".

C2 · Both inputs are converted with int()

input() always returns a string. Wrap each input (or convert credits and labCourses afterwards) with int(...) so the arithmetic works on numbers.

C3 · Tuition uses the constant, with no magic numbers

Multiply credits by TUITION_PER_CREDIT in the termCost formula, and use the constants for every amount: when the office changes a fee, only the constant's line should need editing.

C4 · Both fees come from their constants

Add TECH_FEE once and labCourses * LAB_FEE for the lab courses. The technology fee is per term, so it is not multiplied by anything.

Progressive hints

  1. Work top to bottom in the order of the docstring: constants first, then the inputs, then the computation.

  2. input() gives you text. The number lives inside it until int(...) takes it out.

  3. The technology fee is charged once per term; the lab fee is charged once per lab course. Only one of them gets multiplied.

Reflection: questions and model answers

  1. The test suite includes 0 credits and 0 lab courses. What could that case reveal that the 12-credit case could not?

    With zeros, everything that is multiplied disappears and only the flat technology fee remains, so the output must be exactly $150.0. That isolates TECH_FEE: if it was forgotten, or wrongly multiplied by credits or labs, the zero case shows it immediately, while a large realistic case can hide the mistake inside a big total.

  2. Next year the lab fee rises to $75. Which lines of your program change, and why does that matter for the cost of software?

    Only the line LAB_FEE = 60.0 changes, because every calculation uses the constant. Maintenance is the most expensive phase of the life cycle, so code that turns a policy change into a one-line edit, with no risk of missing a hidden 60 somewhere, is cheaper and safer to maintain.
