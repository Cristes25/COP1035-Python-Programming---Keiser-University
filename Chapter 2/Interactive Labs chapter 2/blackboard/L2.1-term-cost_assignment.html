Lab L2.1-term-cost: Term cost estimator

From request to tested program: the waterfall in miniature

Estimated time: about 25 minutes. Reading: Ch. 2, section 2.1, The Software Development Process and Case Study 2-1 (pp. 27–32).

You will be able to:

  • Turn an analysis and a pseudocode design into working Python
  • Name fixed values as symbolic constants instead of typing magic numbers
  • Convert typed input with int() before doing arithmetic
  • Explain why a test suite checks edge cases such as 0

How to complete it

  1. Open the lab page (L2.1-term-cost.html) from this module. Your work saves automatically in your browser.
  2. Answer the short warm-up about the code you are given, then write your code until every structure check passes.
  3. Use Run to try your code, then run the test program on the lab page; it compares the output for you.
  4. Answer the reflection questions in your own words.
  5. Download (or copy) your lab report.

Submit here: the lab report (.txt) and your code file (term_cost.py).

How it will be assessed

  • Requirements (4 pts): The code meets each requirement. The lab's checks are a guide; the code itself is also read.
  • Behaviour (3 pts): The test program's output matches the expected output.
  • Reflection (2 pts): Answers explain why, in your own words, using the reading's terms.
  • Code quality (1 pt): Readable names, consistent indentation, no leftover dead code.

The checks on the lab page give you feedback; they are not your grade.
