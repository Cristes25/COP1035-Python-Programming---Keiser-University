Couch-to-5K training plan

Objectives

  • Write a count-controlled for loop whose range starts at 1 and includes the upper bound
  • Accumulate a running total with augmented assignment (+=)
  • Skip values with the third (step) argument of range
  • Find and fix an off-by-one error by reading the program's output

Requirements

  1. R1 Number the weeks from 1 through weeks with a two-argument range, so a 4-week plan prints Week 1 to Week 4 (no Week 0, no missing last week).
  2. R2 Inside the loop, add each week's minutes to totalMinutes with augmented assignment (+=).
  3. R3 After a week is counted, make the next week's run longer with minutes += INCREASE (no literal 3).
  4. R4 Print the check-in weeks 1, 4, 7, … up to weeks on the check-in line with a second for loop whose range steps by CHECKIN_EVERY.
  5. R5 Every test case prints the right plan, including 0 weeks (no week lines and a total of 0). (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter with 3 weeks and 20 minutes. Which three week lines does it print, and what two things are wrong with them?

    Week 0 - 20 min, Week 1 - 20 min, Week 2 - 20 min. The numbering starts at 0 because range(3) produces 0, 1, 2, and the minutes never grow because nothing in the loop body changes minutes.

  2. totalMinutes = 0 sits before the loop, not inside it. What would the total be after the loop if that line were moved into the loop body?

    The total would be reset to 0 on every pass, so at the end it would hold only the last week's minutes instead of the sum of all weeks. An accumulator is initialized once, before the loop, and updated inside it.

Solution

training_plan.py
"""
Program: training_plan.py
Author: (your name)
Print a beginner's running plan. Each week's run is
3 minutes longer than the week before.

1. Inputs: number of weeks, minutes in week 1
2. Outputs: one line per week, the total running time,
   and the weeks when the coach checks in (1, 4, 7, ...)
"""

INCREASE = 3        # minutes added each week
CHECKIN_EVERY = 3   # the coach checks in every 3 weeks, from week 1

weeks = int(input("Number of weeks: "))
minutes = int(input("Minutes in week 1: "))

totalMinutes = 0

# One line per week
for week in range(1, weeks + 1):
    print("Week", week, "-", minutes, "min")
    totalMinutes += minutes      # count this week first...
    minutes += INCREASE          # ...then make next week longer

print("Total running time:", totalMinutes, "min")

# Coach check-ins
print("Coach check-ins:", end=" ")
for checkin in range(1, weeks + 1, CHECKIN_EVERY):
    print(checkin, end=" ")
print()

Walkthrough

range(1, weeks + 1) reads as "1 through weeks": the stop value is never produced, so it has to be one past the last week. The order of the two += lines matters: this week's minutes go into the total before minutes grows, otherwise every week is counted 3 minutes too long. When weeks is 0, range(1, 1) is empty, so neither loop body runs and the total stays 0: the empty plan needs no special case. The check-in loop uses a new variable name so it is clear it is not the training week.

Messages students see when a check fails

C1 · Weeks are counted 1 through weeks

Give the week loop two arguments: start at 1 and stop at weeks + 1. range(weeks) counts 0 to weeks - 1, and the stop value itself is never produced, so stopping at weeks would drop the last week.

Hint:

Write the plan for 1 week on paper: which range produces exactly the number 1?

C2 · The total grows with +=

Inside the loop body, add this week's minutes to the accumulator with totalMinutes += minutes. Indent it like the print line so it runs on every pass.

C3 · Each week grows by INCREASE

Make the run longer with minutes += INCREASE, after the total is updated. Use the constant, not 3: if the coach changes the plan, only one line should change.

C4 · Check-ins use a stepped range

Add a second for loop between the two check-in print calls. Its range needs three arguments: start at week 1, stop one past weeks, and step by CHECKIN_EVERY. Print each value with end=" " so they stay on one line.

Progressive hints

  1. range(n) starts at 0. Give range a start value as well as a stop value.

  2. The stop value is never produced, so stop one past the last week you want. For the check-ins, a third argument sets the distance between the numbers.

  3. Order matters inside the loop body: add this week's minutes to the total first, then make the next week longer.

Reflection: questions and model answers

  1. The book calls range(1, 4) written for "1 through 4" an off-by-one error and notes that Python cannot detect it. Which test case here would expose range(1, weeks) most clearly, and what would you see?

    Case 2 (1 week): range(1, 1) is empty, so it would print no week lines and a total of 0 for a one-week plan, an obvious contradiction. Off-by-one errors are logic errors, so only output reveals them, and the smallest cases make the missing iteration easiest to see.

  2. Why is range(1, weeks + 1, CHECKIN_EVERY) better than typing the check-in weeks by hand, for example print(1, 4, 7)?

    The loop works for any plan length: a 2-week plan prints only 1, a 20-week plan prints 1 through 19, with no edits. If the coach switches to every 2 weeks, only the constant changes. A typed list would be wrong for every plan length except one.

Extension

Race day comes after the last week. Add a countdown line such as Weeks to go: 4 3 2 1 that counts down from weeks to 1 with a range whose step is -1. Check it with 1 week and 0 weeks.
