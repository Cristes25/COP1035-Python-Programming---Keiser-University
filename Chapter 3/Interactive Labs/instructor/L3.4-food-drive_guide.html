Food-drive intake log

Objectives

  • Stop a while True loop with break when the user enters a sentinel (the empty string)
  • Combine selection and iteration to skip invalid entries without stopping the loop
  • Track a running count, total and maximum across an unknown number of inputs
  • Prevent a division by zero when the loop body never runs

Requirements

  1. R1 Leave the loop with break when the input is the empty string, before it is converted with float().
  2. R2 If the weight is 0 or less, print exactly Skipped: weight must be more than 0 and do not record it.
  3. R3 For a valid weight, add 1 to count and the weight to totalWeight, both with +=.
  4. R4 Keep heaviest up to date: when a valid weight is larger than heaviest, replace it.
  5. R5 Print the four summary lines only when count is greater than 0; otherwise print No donations recorded.
  6. R6 Every test shift prints the right log: a normal shift, an empty shift, typos, and a typo in the middle. (verified by the program output)

Before you code: warm-up and model answers

  1. In the starter, a volunteer presses Enter at the first prompt. Which line fails, and why?

    weight = float(data) fails with a ValueError, because input returned the empty string and an empty string is not a number. The loop has no exit, so the sentinel value reaches the conversion.

  2. Why is the input call inside the loop here, rather than once before it as in the book's first summation example?

    With while True the prompt must run at least once and on every pass, so a single input at the top of the body replaces the two input statements (one before the loop, one at the bottom) that a priming-read loop needs. The exit test then happens in the middle of the body.

Solution

food_drive.py
"""
Program: food_drive.py
Author: (your name)
Log donations at the food-drive table.

A volunteer types the weight of each donation in pounds and
just presses Enter when the shift ends. Typos such as 0 or a
negative weight are skipped with a message. At the end, the
program prints how many donations were logged, their total and
average weight, and the heaviest one.
"""

count = 0          # donations recorded
totalWeight = 0.0  # pounds recorded
heaviest = 0.0     # heaviest donation so far

while True:
    data = input("Weight (Enter to end): ")
    if data == "":
        break                      # the shift is over
    weight = float(data)
    if weight <= 0:
        print("Skipped: weight must be more than 0")
    else:
        count += 1
        totalWeight += weight
        if weight > heaviest:
            heaviest = weight

if count > 0:
    print("Donations: %d" % count)
    print("Total weight: %0.1f lb" % totalWeight)
    print("Average: %0.2f lb" % (totalWeight / count))
    print("Heaviest: %0.1f lb" % heaviest)
else:
    print("No donations recorded.")

Walkthrough

The input has to be tested as a string first, because float("") raises an error: that is why the break comes before the conversion. while True guarantees the prompt runs at least once, and the single exit makes the loop easy to read. The if-else inside the loop keeps typos out of all three running values. After the loop, count > 0 guards the average: totalWeight / count is only evaluated when it is safe. Starting heaviest at 0.0 works because every recorded weight is more than 0.

Messages students see when a check fails

C1 · Enter ends the loop before float()

Right after the input line, test if data == "": and break in its body. The test must come before float(data): the empty string cannot be converted to a number.

Hint:

Pressing Enter without typing gives input an empty string.

C2 · Weights of 0 or less are skipped

Use an if-else on the weight: weight <= 0 prints the skip message, the else records the donation. A weight of exactly 0 is a typo too, so < 0 is not enough.

C3 · Count and total grow with +=

In the branch for a valid weight, add count += 1 and totalWeight += weight. Both belong only in that branch, so typos are not counted.

C4 · The heaviest donation is tracked

Compare each valid weight with heaviest and replace heaviest when the new weight is larger (a one-way if, or max(heaviest, weight)).

C5 · The summary is guarded against an empty shift

Put the four summary lines in the if part of if count > 0: and print No donations recorded. in the else. Without the guard, an empty shift divides by zero when it computes the average.

Progressive hints

  1. Test the raw string before you convert it. What does input return when the volunteer presses Enter without typing?

  2. Inside the loop, an if-else chooses between skipping and recording. Only the recording branch touches count, totalWeight and heaviest.

  3. After the loop, indent the four summary prints under an if on count; the else prints the message for an empty shift.

Reflection: questions and model answers

  1. Section 3.4 says to test a loop with data that make it run 0 times, once, and at least 5 times. Which test shifts cover those, and what bug could each one reveal?

    Case 2 runs the body zero times for recording (Enter right away): it reveals a missing guard on the average (division by zero). Case 3 records exactly one donation after two typos: it checks that typos are not counted and that a single value becomes the heaviest. Case 4 runs the loop six times with a typo in the middle: it shows that the loop keeps going after a skip and that the maximum is updated correctly over many passes.

  2. heaviest starts at 0.0. Why is that safe in this program? What would go wrong if the same code were used to find the coldest temperature in a list of readings, starting from 0.0?

    Every recorded weight is more than 0, so the first valid donation always replaces 0.0. For the coldest temperature (a minimum) starting at 0.0, any day above freezing would never replace it, and the program would report 0.0 even if no reading was 0. A safer start is the first actual value, or a guard on the count.

Extension

Volunteers sometimes type twelve instead of 12, which crashes float(). Without try/except (later in the book), how could you check the string before converting it? Look up the string method isdigit() and note which valid weights it would wrongly reject.
