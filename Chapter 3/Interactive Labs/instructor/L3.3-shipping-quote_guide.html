Bookstore shipping quote

Objectives

  • Trap invalid input with an if-else and a compound condition built with or
  • Order the conditions of a multiway if so the first true condition is the right one
  • Combine two requirements with and, choosing >= versus > deliberately
  • Design test data around boundary values, as section 3.3 recommends

Requirements

  1. R1 Check the weight first. If it is 0 or less or more than MAX_WEIGHT, print exactly Error: weight must be more than 0 and at most 70 lb and no price; otherwise price the package.
  2. R2 Fix the multiway if so each weight lands in its own tier: order the conditions so the first true one is the right one (2 lb pays $5.00, 2.5 lb pays $9.50).
  3. R3 Make shipping $0.00 only when the customer is a member (y) and the subtotal is at least FREE_SHIPPING_MIN. Exactly $35.00 qualifies.
  4. R4 All ten boundary tests print the right quote or error. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter's chain for a 1.5 lb package. Which branch runs and what does it charge? Why can the weight <= 10 and weight <= 2 branches never run, for any weight?

    weight <= 30 is True for 1.5, so the first branch runs and charges $15.00; the rest of the chain is skipped. Any weight that is at most 10 or at most 2 is also at most 30, so the first condition always catches it first: those branches are unreachable.

  2. The rule says members ship free on orders of "$35.00 or more". Which comparison operator does that call for, and which single test value would expose the wrong one?

    >= (greater than or equal). A subtotal of exactly 35.00 exposes the mistake: with > it would be charged, with >= it ships free.

Solution

shipping_quote.py
"""
Program: shipping_quote.py
Author: (your name)
Quote the shipping cost of a campus bookstore order.

Rates by package weight (pounds):
   up to 2 lb ............. $5.00
   over 2, up to 10 lb .... $9.50
   over 10, up to 30 lb ... $15.00
   over 30 lb ............. $25.00
Packages must weigh more than 0 lb and at most 70 lb.
Rewards members ship free on orders of $35.00 or more.
"""

MAX_WEIGHT = 70            # heaviest package the carrier accepts
FREE_SHIPPING_MIN = 35.00  # members ship free from this subtotal

weight = float(input("Package weight (lb): "))
subtotal = float(input("Order subtotal ($): "))
member = input("Rewards member? (y/n): ")

if weight <= 0 or weight > MAX_WEIGHT:
    print("Error: weight must be more than 0 and at most 70 lb")
else:
    # Lightest tier first: the first true condition wins
    if weight <= 2:
        shipping = 5.00
    elif weight <= 10:
        shipping = 9.50
    elif weight <= 30:
        shipping = 15.00
    else:
        shipping = 25.00

    if member == "y" and subtotal >= FREE_SHIPPING_MIN:
        shipping = 0.00

    print("Shipping: $%0.2f" % shipping)

Walkthrough

A multiway if stops at the first true condition, so with <= tests the narrowest tier (2 lb) must come first; the descending form (> 30, then > 10, then > 2), like the book's grade converter, is equally correct. Putting all the pricing in the else of the weight check means a bad weight can never reach it, and the price line is not printed for an error. The member rule needs both conditions, so and; "at least" means >=, which is exactly what the $35.00 test case checks.

Messages students see when a check fails

C1 · Bad weights are trapped with one compound condition

Before the pricing chain, test weight <= 0 or weight > MAX_WEIGHT and print the error in that branch; put all the pricing in the else. Use MAX_WEIGHT, not 70, in the condition.

Hint:

One condition for each way the weight can be wrong; either one is enough to reject it.

C2 · Tiers are tested in a working order

Reorder the chain so the first true condition is the correct tier: with <= tests, start with weight <= 2, then <= 10, then <= 30, and let else catch the heaviest packages. (Testing from the top with > works too.)

C3 · Free shipping needs membership and the subtotal

Set shipping to 0.00 under one if that joins member == "y" and the subtotal test with and: both must be true. Use FREE_SHIPPING_MIN, not 35.

C4 · Exactly $35.00 qualifies

"$35.00 or more" includes $35.00 itself, so compare with >=. With >, a member spending exactly $35.00 would still be charged.

Progressive hints

  1. A multiway if runs only the first branch whose condition is true. Which tier's condition is true for the fewest weights? That one has to be tested first.

  2. Validate first: if the weight is bad, print the error; put the whole pricing chain and the price line inside the else (indented one more level).

  3. "At least" includes the limit itself. Join the membership test and the subtotal test so both must hold.

Reflection: questions and model answers

  1. The tests use 2, 2.5, 10, 30, 45, 70.5 and 0 lb rather than, say, 5, 20 and 50. Using section 3.3's advice on testing conditions, explain how these values were chosen.

    They sit on or just past each boundary in the conditions: 2 and 2.5 test the edge between the first two tiers, 10 and 30 test the other edges, 0 and 70.5 test the two error limits, and 45 covers the else branch. Values in the middle of a tier would pass even with < instead of <=, so they cannot catch boundary mistakes, while these exercise every branch and every edge.

  2. The weight check can reject with weight <= 0 or weight > MAX_WEIGHT, or accept with weight > 0 and weight <= MAX_WEIGHT. How are the two conditions related, and does it matter which one goes in the if?

    One is exactly the negation of the other: not (A and B) equals (not A) or (not B). Either works if the branches are swapped: with the or version the error goes in the if part, with the and version the pricing goes in the if part and the error in the else. Choose the one that reads most naturally for the reader.
