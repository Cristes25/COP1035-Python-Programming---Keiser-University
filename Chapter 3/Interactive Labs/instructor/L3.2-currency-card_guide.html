Study-abroad currency card

Objectives

  • Left- and right-justify values in a field with %-<width> and %<width>
  • Show money with exactly two decimals using %<width>.2f
  • Format several values at once with a tuple after the % operator
  • Line up a table header with its columns by reusing the same field widths

Requirements

  1. R1 Print the header with one format string and a tuple: Dollars left-justified in 8, Euros right-justified in 10, After fee right-justified in 12.
  2. R2 Print each row with one format string and the tuple (dollars, euros, afterFee): dollars as a left-justified integer in 8, the two euro amounts right-justified in 10 and 12 with two decimals.
  3. R3 Print the last line as Rate used: 1 USD = 0.9200 EUR, with the rate formatted to exactly four decimals.
  4. R4 Every test card matches the expected output character for character, including a card too small to have any rows. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter prints each row with print(dollars, euros, afterFee). Why do the columns drift out of line once the dollar amounts reach three digits?

    print starts each value right after the previous one plus a single space, so every value begins wherever the previous one ended. When 80 becomes 100 the dollars take one more character and push the rest of the row one column to the right. A field width fixes how many columns each value occupies.

  2. In the format code %10.2f, what do the 10 and the 2 each control? How many spaces go in front of 18.40 in that field?

    10 is the field width, the total number of characters including the decimal point; 2 is the precision, the digits after the point. 18.40 is 5 characters, so 5 spaces are added on its left to right-justify it in 10.

Solution

currency_card.py
"""
Program: currency_card.py
Author: (your name)
Print a pocket conversion card for students travelling to Europe.

1. Inputs: today's rate (euros per dollar), largest amount on the card
2. Output: a table with one row per $20 step:
   dollars, euros, and euros left after the card's 3% fee,
   followed by the rate that was used
"""

STEP = 20         # dollar amounts go up in steps of $20
FEE_RATE = 0.03   # the bank card's foreign-transaction fee

rate = float(input("Euros per dollar: "))
largest = int(input("Largest amount in dollars: "))

# Table header: the same widths as the rows below
print("%-8s%10s%12s" % ("Dollars", "Euros", "After fee"))

# One row per amount
for dollars in range(STEP, largest + 1, STEP):
    euros = dollars * rate
    afterFee = euros - euros * FEE_RATE
    print("%-8d%10.2f%12.2f" % (dollars, euros, afterFee))

print("Rate used: 1 USD = %0.4f EUR" % rate)

Walkthrough

The header and the rows share the widths 8, 10 and 12, and the same justification, so every heading ends (or starts) exactly where its numbers do. %-8d pads the dollars with spaces on the right; %10.2f pads on the left and counts the decimal point and both decimals in the 10. Formatting only changes how a value is shown: afterFee still holds 17.848 after the row prints 17.85. With a largest amount of 10, range(20, 11, 20) is empty, so the card has a header and the rate line but no rows.

Messages students see when a check fails

C1 · The header uses the column widths

Print the header with "%-8s%10s%12s" % (...) and the three headings in a tuple. The minus sign left-justifies Dollars; the widths must match the rows exactly or the headings will not sit over their columns.

C2 · Rows are formatted with width and precision

Replace the row's print with one format string, %-8d for the dollars, then %10.2f and %12.2f, followed by % (dollars, euros, afterFee) in that order. Each code in the string is matched to the value in the same position of the tuple.

C3 · The rate shows four decimals

Format the rate with %0.4f inside the Rate used string and put % rate after it. A field width of 0 means "no padding": the value takes just the space it needs.

Progressive hints

  1. The number after % is the field width. A minus sign in front of it moves the value to the left edge of the field.

  2. Put all the values for one line in a tuple after the % operator, in the same order as their format codes.

  3. In %<width>.<precision>f, the width counts the decimal point and the decimals too. The header can reuse the same widths with s codes.

Reflection: questions and model answers

  1. The header uses exactly the same widths as the rows. What would a reader see if the header gave Euros a width of 9 while the rows kept 10?

    Every heading after Dollars would shift one column to the left of its numbers: Euros would end one character before the euro amounts and After fee would also be off by one. Columns only line up when header and rows reserve the same number of characters for each field.

  2. The card shows 17.85, but afterFee still holds 17.848. If someone added up the printed After fee column, could their total differ from adding the stored values and printing that sum? What should a real receipt do?

    Yes. Rounding each row and then adding can differ by a cent or more from adding the exact values and rounding once, because each row's rounding error accumulates. A receipt should round each line to cents first and then total the rounded amounts, so the printed numbers add up.
