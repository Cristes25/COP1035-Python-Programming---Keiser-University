Recursive structure: the shared-drive storage report

Objectives

  • Recognise a recursive structure: a folder contains files and other folders, which contain files and other folders
  • Write recursive functions that loop over a folder's items and call themselves on each subfolder, as countFiles and countBytes do in Case Study 7-1
  • Build and return a list from recursive calls, passing down extra information (the path) as an argument

Requirements

  1. R1 count_files counts each file once and, for each subfolder, adds the result of a recursive call on that subfolder.
  2. R2 total_kb adds each file's size and, for each subfolder, the result of a recursive call. It contains no nested loop.
  3. R3 find_files searches subfolders with a recursive call that passes the longer path (path + name + "/"), adds that call's list to its own, and returns full paths such as media/events/fair.jpg.
  4. R4 All three functions work on an empty folder and on folders nested deeper than the club's drive. (verified by the program output)

Before you code: warm-up and model answers

  1. Run the starter (or reason it out). What do count_files(DRIVE) and total_kb(DRIVE) return, and which files does each one miss or miscount?

    count_files returns 4: it counts the top-level names, so the folders minutes and media count as one file each and nothing inside them is counted. total_kb returns 402 (48 + 22 + 19 + 310 + 3): it sees minutes and logo.png one level down but misses everything in media/events.

  2. The finished count_files(DRIVE) calls itself for minutes, media and events. What is the largest number of count_files stack frames on the call stack at the same time, and when does that happen?

    Three: while counting media/events, the frames for DRIVE, media and events are all on the stack. The events call returns 3 and is removed, then the media call finishes and returns, and the top call carries on.

Solution

drive_report.py
"""drive_report.py - storage report for the robotics club's shared drive.

A folder is a dictionary. Each key is a name; each value is either a file
size in KB (an int) or another folder (a dictionary).
"""

DRIVE = {
    "budget.xlsx": 48,
    "minutes": {"jan.docx": 22, "feb.docx": 19},
    "media": {
        "logo.png": 310,
        "events": {"fair.jpg": 2400, "gala.jpg": 3100, "fair_map.pdf": 640},
    },
    "readme.txt": 3,
}


def is_folder(item):
    """Return True if item is a folder (a dictionary), False if it is a file size."""
    return isinstance(item, dict)


def count_files(folder):
    """Return the number of files in folder and all its subfolders."""
    count = 0
    for name in folder:
        if is_folder(folder[name]):
            count += count_files(folder[name])
        else:
            count += 1
    return count


def total_kb(folder):
    """Return the total size in KB of folder and all its subfolders."""
    total = 0
    for name in folder:
        item = folder[name]
        if is_folder(item):
            total += total_kb(item)
        else:
            total += item
    return total


def find_files(target, folder, path=""):
    """Return the paths of the files whose names contain target, in folder
    and all its subfolders. path is the folder's own path, such as "media/"."""
    files = []
    for name in folder:
        item = folder[name]
        if is_folder(item):
            files.extend(find_files(target, item, path + name + "/"))
        elif target in name:
            files.append(path + name)
    return files


def main():
    """Print the drive's file count, total size and the files matching a search."""
    target = input("Search for? ")
    print("Files:", count_files(DRIVE))
    print("Total:", total_kb(DRIVE), "KB")
    matches = find_files(target, DRIVE)
    if not matches:
        print("No matches")
    for path in matches:
        print(path)


if __name__ == "__main__":
    main()

Walkthrough

Each function has the shape of countFiles and countBytes in the case study: loop over the folder's items; a file is handled directly, and a subfolder is handed to a recursive call whose result is added in. There is no explicit if for the base case: a folder with no subfolders makes no recursive call, so the recursion ends there, and an empty folder returns 0 or []. Because each call goes one level deeper into a finite drive, the recursion always ends. In find_files, the default argument path="" lets callers start at the top without a path, and each recursive call passes the path to the subfolder. files.extend(...) and files += ... are both correct; files.append(...) with a recursive call would put a list inside the list. The nested-loop version can only reach as many levels as it has loops; recursion reaches any depth with one function.

Messages students see when a check fails

C1 · count_files calls itself on subfolders

Inside the loop, use is_folder to tell files from folders. For a file add 1; for a folder add count_files(...) of that folder, which counts everything inside it, however deep.

C2 · total_kb calls itself on subfolders

When an item is a folder, add total_kb(item) to the total. The recursive call adds up that folder and every folder inside it.

C3 · total_kb has no nested loop

Remove the inner for loop. Each nested loop reaches one more level and no further; one recursive call replaces it and reaches every level.

C4 · find_files calls itself and keeps the matches it returns

For a subfolder, call find_files on it and add the list it returns to files with files.extend(...) (as findFiles does in the case study). append would put a whole list inside your list.

C5 · find_files passes the longer path down and returns full paths

Pass path + name + "/" as the third argument of the recursive call, and append path + name for a match. Each call then knows where it is in the drive.

Progressive hints

  1. Look at countFiles in Case Study 7-1: for each element, a file adds 1 to the count, and a directory adds whatever the recursive call returns for that directory.

  2. In total_kb, the inner loop is trying to do the job total_kb itself already does, for a single folder. What if you just asked total_kb for that subfolder's total?

  3. In find_files, the recursive call returns a list. Your own list needs its items, not the list as one item, so join them with extend. The subfolder's path is your path, its name and a slash.

Reflection: questions and model answers

  1. None of your functions has an if that says "stop". Where is the base case, and why can't these functions recurse forever on the club's drive?

    The base case is a folder with no subfolders: the loop handles only files and makes no recursive call, so that call simply returns. Each recursive call goes one level deeper into a drive that has a finite depth, so eventually every call reaches folders without subfolders.

  2. Explain why recursion fits this problem better than loops, using what happened to the teammate's nested-loop total_kb.

    The drive has a recursive structure: a folder holds folders, which hold folders. Each nested loop reaches one more level, so the teammate's version stopped at media and missed media/events. One recursive function handles a folder the same way at every level, so it works for any depth, including folders added later.

  3. Why does find_files take path as an argument with a default, instead of building the path some other way?

    Each call only sees its own folder, not where it sits in the drive, so the caller has to pass that information down: the recursive call gets path + name + "/". The default "" means the first call, at the top of the drive, doesn't need to pass a path.
