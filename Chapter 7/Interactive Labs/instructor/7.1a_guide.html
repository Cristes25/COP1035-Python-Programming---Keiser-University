Base case and recursive step: the pyramid workout planner

Objectives

  • Convert a while loop into a recursive function by replacing the loop with a selection statement and the update with a recursive call
  • Write a recursive function that returns a value, with a base case that ends the recursion
  • Make sure every recursive step moves the argument toward the base case, so the recursion can't run forever

Requirements

  1. R1 show_sets contains no loop. It prints the current set inside an if, then calls itself for the next set (reps + 2).
  2. R2 total_reps has a base case: when there are no sets left (reps is past peak), it returns 0.
  3. R3 The recursive call in total_reps passes reps + 2, so each call moves toward the base case.
  4. R4 The base case uses an inequality, not ==, so a peak the reps never land on exactly (4 up to 11) still ends the recursion, and a start above the peak returns 0.
  5. R5 The test program's plans and totals match. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's total_reps(6, 10) returns reps + total_reps(reps, peak). Without running it, describe the calls it makes and explain how Python finally stops it.

    It calls total_reps(6, 10), which calls total_reps(6, 10) again, and so on: the argument never changes and there is no base case. Each call adds a stack frame, so after about 1000 calls Python halts with RecursionError: maximum recursion depth exceeded.

  2. Trace the starter's loop version of show_sets(5, 9): which lines does it print, and what value of reps makes the loop stop?

    It prints Set: 5 reps, Set: 7 reps and Set: 9 reps. Then reps becomes 11, 11 <= 9 is False, and the loop stops.

Solution

pyramid.py
"""pyramid.py - plan a pyramid workout: each set climbs by 2 reps up to a peak."""


def show_sets(reps, peak):
    """Print one line per set, from reps up to peak, climbing by 2."""
    if reps <= peak:
        print("Set:", reps, "reps")
        show_sets(reps + 2, peak)


def total_reps(reps, peak):
    """Return the total number of reps in the sets from reps up to peak."""
    if reps > peak:
        return 0
    else:
        return reps + total_reps(reps + 2, peak)


def main():
    """Ask for the first set and the peak, then print the plan."""
    start = int(input("First set reps? "))
    peak = int(input("Peak reps? "))
    show_sets(start, peak)
    print("Total:", total_reps(start, peak), "reps")


if __name__ == "__main__":
    main()

Walkthrough

This is the same conversion the reading makes for displayRange: the loop's condition becomes the if, and the assignment reps = reps + 2 becomes the argument of the recursive call. In total_reps, the base case (reps > peak, return 0) is what stops the recursion; the recursive step adds the current set to the total of the sets after it, exactly like the reading's summation. The starter's call total_reps(reps, peak) never changes its argument, so every call makes the same call again until Python stops it with RecursionError. A base case of reps == peak works for 6 to 10 but not for 4 to 11: 10 + 2 is 12, which skips 11, and the recursion runs on forever. Equivalent correct forms: if reps <= peak: return reps + total_reps(reps + 2, peak) followed by return 0.

Messages students see when a check fails

C1 · show_sets uses no loop

Remove the while loop from show_sets. In a recursive version, the if decides whether there is another set to print, and the recursive call does the repeating.

C2 · show_sets calls itself with the next set

Inside an if reps <= peak: block, print the set, then call show_sets again with reps + 2 and the same peak. The + 2 moves from the old assignment into the argument.

C3 · total_reps returns 0 in a base case

Add a selection statement to total_reps that returns 0 when there are no sets left. Without a base case, nothing ever stops the calls.

C4 · The recursive call moves toward the base case

Call total_reps with reps + 2, not reps. If the argument never changes, each call repeats the previous one until Python runs out of stack frames.

C5 · The base case uses an inequality, not ==

Test the base case with > (or <= for the recursive case). With ==, a plan from 4 to 11 goes 4, 6, 8, 10, 12, ... and never equals 11, so the recursion never stops.

Progressive hints

  1. Compare the two displayRange functions in the reading: the while became an if, and lower = lower + 1 disappeared because the new value is passed straight into the recursive call.

  2. For total_reps, follow the reading's summation: one branch returns 0 when the range is empty; the other returns the current value plus a recursive call on the rest of the range.

  3. Ask what the last call looks like for 4 up to 11: reps is 12. Your base case has to recognise 12 as "no sets left", and 12 == 11 is False.

Reflection: questions and model answers

  1. Your base case uses > (or <=) instead of ==. Explain, using the 4-to-11 plan, why == would turn a working function into infinite recursion.

    The reps go 4, 6, 8, 10, 12. With == the base case asks whether reps equals 11, which never happens because the step of 2 jumps over it, so the calls continue past 12, 14, ... until RecursionError. With > peak, 12 is past the peak, so the recursion stops there.

  2. How many calls of total_reps does total_reps(6, 10) make, counting the first, and what does the call stack hold while the deepest call runs?

    Four calls: (6, 10), (8, 10), (10, 10) and (12, 10). While the last one runs, the stack holds four stack frames, one per call, each with its own reps and peak and a return address; each frame waits for the call above it to return before adding its reps.

  3. The reading says a loop solves the same problem with a constant amount of memory. When would you still choose the recursive version, and when the loop?

    Recursion fits when the problem has a recursive structure and stays small, because the code follows the definition directly (a total is this set plus the total of the rest). For thousands of steps a loop is better: it uses a few variables instead of one stack frame per call and can't hit the recursion limit.
