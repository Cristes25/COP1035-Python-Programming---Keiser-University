Functions as data: the step-counter weekly report

Objectives

  • Pass a function as an argument to map and filter, without calling it
  • Write a predicate that returns a Boolean, and use it with filter to keep only the values that pass
  • Replace a loop that builds a list with a mapping, passing the map object straight to join as the reading does in changePerson

Requirements

  1. R1 parse_steps converts the pieces of the line with map(int, ...) and returns a list. It has no loop.
  2. R2 worn is a predicate: it returns True or False, and only -1 counts as not worn (a day with 0 steps was worn). worn_days returns the list that filter with worn produces.
  3. R3 km_report maps a helper function (nested in km_report, or a lambda) onto days and passes the map object directly to join. It has no loop and doesn't build a list first.
  4. R4 goal_days counts the days with at least GOAL steps using filter and a predicate, with no loop.
  5. R5 The test program's results match, including an empty week. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's worn returns steps itself. If worn_days used filter(worn, [-1, 9100, 0]), which values would it keep, and why?

    It would keep -1 and 9100 and drop 0. filter keeps a value when the function returns something true, and every number except 0 counts as true, so the not-worn -1 day stays in and a real 0-step day disappears: the opposite of what we want.

  2. What is the difference between map(int, pieces) and map(int(), pieces)? Which one does the reading use, and what goes wrong with the other?

    map(int, pieces) passes the function itself, and map calls it on each piece; that is what the reading does. int() calls the function right away with no argument and returns 0, so map receives the number 0 instead of a function and fails because 0 is not callable.

Solution

steps.py
"""steps.py - weekly report from a fitness watch export."""

KM_PER_STEP = 0.0008
GOAL = 8000


def parse_steps(line):
    """Convert a line such as "8200, 10450, -1" into a list of ints."""
    return list(map(int, line.split(",")))


def worn(steps):
    """Predicate: True if the watch was worn that day. The watch writes -1
    for a day it wasn't worn; 0 is a real (very lazy) day."""
    return steps >= 0


def worn_days(days):
    """Return a list of the step counts for the days the watch was worn."""
    return list(filter(worn, days))


def km_report(days):
    """Return a line such as "6.6 km | 8.4 km" for the given step counts."""
    def to_km(steps):
        return "%.1f km" % (steps * KM_PER_STEP)
    return " | ".join(map(to_km, days))


def met_goal(steps):
    """Predicate: True if the day reached at least GOAL steps."""
    return steps >= GOAL


def goal_days(days):
    """Return how many days reached at least GOAL steps."""
    return len(list(filter(met_goal, days)))


def main():
    """Read one week of steps and print the report."""
    line = input("This week's steps? ")
    days = worn_days(parse_steps(line))
    print("Days worn:", len(days))
    print("Distance:", km_report(days))
    print("Goal met on", goal_days(days), "days")


if __name__ == "__main__":
    main()

Walkthrough

map(int, line.split(",")) applies int to each piece; int ignores the spaces around the digits, so " 10450" is fine. Note int, not int(): the function itself is the argument. map and filter return map and filter objects, so parse_steps and worn_days wrap them in list because their callers need a list (len doesn't work on a filter object). km_report doesn't: join accepts the map object directly, just as in the reading's changePerson. The starter's worn returned steps itself: filter then treats -1 as true (any nonzero number is truthy) and 0 as false, the opposite of what we want, which is why the reading insists that the function given to filter be a predicate. steps >= 0 and steps != -1 are both correct; steps > 0 drops real 0-step days. In goal_days, >= fixes the exactly-8000 bug. A lambda (section 7.2's next topic) is also accepted in km_report and goal_days.

Messages students see when a check fails

C1 · parse_steps maps int onto the pieces

Use map(int, line.split(",")) and wrap it in list(...). Pass int itself, without parentheses: map calls it once for each piece.

C2 · parse_steps has no loop

Remove the for loop and the append. The mapping does both jobs in one line.

C3 · worn returns a Boolean comparison

Return a comparison, so worn gives True or False: steps >= 0 or steps != -1. Only -1 means the watch wasn't worn; steps > 0 would also drop a real day of 0 steps.

C4 · worn_days filters with worn

Return list(filter(worn, days)). filter applies the predicate to each value and keeps the ones for which it returns True.

C5 · km_report passes a mapping straight to join

Define a small helper inside km_report (such as to_km(steps)) that formats one day, then return " | ".join(map(to_km, days)). join accepts the map object directly, so there is no loop and no list to build.

C6 · goal_days counts with filter, no loop

Write a predicate that checks steps >= GOAL, then return len(list(filter(<predicate>, days))). A filter object has no length, so turn it into a list first.

  2. Try the starter's worn in your head on -1 and on 0. filter keeps a value when the function's result is true, and every number except 0 counts as true.

Reflection: questions and model answers

  1. The reading says a higher-order function separates transforming each value from accumulating the results. Point to where that separation is in your km_report.

    The nested helper to_km transforms one day's steps into a string such as 8.4 km; it knows nothing about lists. map applies it to every day and join accumulates the results into one line. The starter mixed both jobs in one loop with append.

  2. Why do parse_steps and worn_days wrap their result in list(...), while km_report passes the map object straight to join?

    map and filter return map and filter objects, not lists. main needs a real list from worn_days because it calls len on it and passes it on more than once, and a map object can be used only once. join only needs to go through the values once, so the map object is enough.

  3. You chose steps >= 0 (or steps != -1) for worn, not steps > 0. Explain the difference for the report and why it matters.

    -1 is the watch's code for not worn, but 0 is a real measurement: the student wore the watch and didn't walk. steps > 0 would drop that day, making Days worn too low and hiding an inactive day from the report. The predicate must match what the data means.
