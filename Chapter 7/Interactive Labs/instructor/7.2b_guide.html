Reducing, lambda and a jump table: the club treasurer's tool

Objectives

  • Use functools.reduce with a lambda and an initial value, so the reducing also works on an empty list
  • Create a predicate on the fly with lambda and use it with filter
  • Replace a multiway selection statement with a jump table: a dictionary of functions keyed by command

Requirements

  1. R1 show_total uses reduce with a lambda and the initial value 0, so an empty ledger prints Total: $0.00.
  2. R2 show_big builds its list with filter and a lambda, with no loop. An expense of exactly $50 counts as big.
  3. R3 JUMP_TABLE is a dictionary that maps "1", "2" and "3" to the functions show_total, show_big and add_expense themselves, without calling them.
  4. R4 run_command has no if/elif chain: it looks the command up in JUMP_TABLE and calls the function it finds. An unknown command calls unknown_command.
  5. R5 The test program's results match, including an empty ledger and an unknown command. (verified by the program output)

Before you code: warm-up and model answers

  1. The starter's show_total calls reduce(lambda x, y: x + y, expenses). Using the reading's three examples, what happens with three expenses, with one, and with none?

    With three, it adds them left to right and prints the sum. With one, reduce returns that single item. With none, it raises TypeError: reduce() of empty iterable with no initial value, because there are no values to start from.

  2. A teammate writes JUMP_TABLE = {"1": show_total(), "2": show_big()}. What happens when this line runs, and what does JUMP_TABLE["1"] hold afterwards?

    The parentheses call both functions immediately, while the dictionary is being built, so the total and the big expenses print at start-up. Each function returns None, so JUMP_TABLE["1"] holds None, and JUMP_TABLE["1"]() fails with TypeError: 'NoneType' object is not callable.

Solution

ledger.py
"""ledger.py - the robotics club treasurer's expense tool."""

from functools import reduce

BIG = 50
expenses = [42.50, 18.25, 120.00]


def show_total():
    """Print the sum of all expenses."""
    print("Total: $%.2f" % reduce(lambda x, y: x + y, expenses, 0))


def show_big():
    """Print the expenses of at least BIG dollars, or none."""
    big = list(filter(lambda a: a >= BIG, expenses))
    if big:
        print("Big:", ", ".join(map(lambda a: "$%.2f" % a, big)))
    else:
        print("Big: none")


def add_expense():
    """Ask for an amount and add it to the ledger."""
    amount = float(input("Amount? "))
    expenses.append(amount)
    print("Added $%.2f" % amount)


def unknown_command():
    """Tell the user the command doesn't exist."""
    print("Unknown command")


JUMP_TABLE = {"1": show_total, "2": show_big, "3": add_expense}


def run_command(command):
    """Carry out one menu command."""
    JUMP_TABLE.get(command, unknown_command)()


def main():
    """Read commands until the user enters q."""
    while True:
        command = input("Command (1 total, 2 big, 3 add, q quit)? ")
        if command == "q":
            break
        run_command(command)


if __name__ == "__main__":
    main()

Walkthrough

reduce(lambda x, y: x + y, expenses, 0) places 0 before the items, so the sum of an empty ledger is 0 instead of a TypeError; with items, it computes ((0 + 42.5) + 18.25) + ... sum(expenses) would do the same job, but this lab practises reducing. The lambda in show_big is a predicate built on the fly: lambda a: a >= BIG. In the jump table the values are show_total, not show_total(): with parentheses, Python would call each function while building the dictionary (printing the total at start-up) and store its return value, None. JUMP_TABLE.get(command, unknown_command)() looks up the function, falling back to unknown_command for an unknown key, then calls it with (). An if command in JUMP_TABLE: test followed by JUMP_TABLE[command]() is also correct. The table is defined after the functions, because their names must exist when the dictionary is built.

Messages students see when a check fails

C1 · reduce gets the initial value 0

Add a third argument to reduce: reduce(lambda x, y: x + y, expenses, 0). The initial value is placed before the items and is the result when the list is empty.

C2 · show_big filters with a lambda

Replace the loop with list(filter(lambda a: a >= BIG, expenses)). The lambda is the predicate, written on the spot because nothing else needs it; >= makes $50 count as big.

C3 · JUMP_TABLE maps each command to its function

Fill the dictionary: JUMP_TABLE = {"1": show_total, "2": show_big, "3": add_expense}. The keys are the strings input returns; the values are the functions.

C4 · The table stores functions, it doesn't call them

Remove the parentheses after the function names in JUMP_TABLE. show_total() runs the function right away and stores its return value (None); show_total stores the function, to be called later.

C5 · run_command looks the command up instead of testing it

Replace the if/elif chain with one lookup: JUMP_TABLE.get(command, unknown_command)(). get returns the function for the command, or unknown_command if there is none, and the final () calls it.

Progressive hints

  1. Read the help(reduce) text in the reading's Fail-Safe Programming box: reduce(function, iterable[, initial]). What does it say about the initial value and empty iterables?

  2. A lambda for filter is a whole predicate in one expression: lambda <name>: <a comparison>. Compare against BIG, and decide between > and >= for an expense of exactly $50.

  3. In the jump table, the value for "1" should be the function itself, the same way f = abs makes an alias in the reading. In run_command, a dictionary's get takes a second argument used when the key is missing.

Reflection: questions and model answers

  1. The reading says that with a jump table, maintaining the command processor "becomes a matter of data management". Explain what changes when the club adds a command 4 for export.

    With the if/elif chain I would edit run_command and add another branch, risking a typo in the logic. With the jump table I write an export function and add one entry, "4": export, to the dictionary (and the menu). run_command doesn't change at all.

  2. Why is a lambda a good fit for filter in show_big and for the sum in show_total, and what can't a lambda contain?

    Both functions are tiny and used only in that one place, so naming them with def would add a function nobody else calls. A lambda defines it on the spot. A lambda holds a single expression on one line, so it can't contain a statement such as if/else or a loop.

  3. What does the initial value 0 change in reduce(lambda x, y: x + y, expenses, 0), both for an empty ledger and for a full one?

    For an empty ledger, reduce returns the initial value 0 instead of raising TypeError. For a full one, 0 is placed before the items, so it computes ((0 + 42.5) + 18.25) + ...; adding 0 doesn't change the sum, so the result is the same as before.
