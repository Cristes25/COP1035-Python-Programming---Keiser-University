Sensible defaults: progress bars for the study tracker

Objectives

  • Write a function header with required arguments first, followed by default arguments
  • Call a function using its defaults, overriding a default by position, and overriding one by keyword
  • Choose defaults so the most common call is also the simplest

Requirements

  1. R1 The header is progress_bar(done, total, width=20, fill="#"): the two required arguments first, then the two default arguments.
  2. R2 When done is greater than total, the bar is full and shows 100%. It never draws more than width characters.
  3. R3 The dashboard call passes only the two required arguments.
  4. R4 The phone call overrides only the width (10). The printable call overrides only the fill ("=") by keyword, leaving the width at its default. No call passes a default value explicitly.
  5. R5 The test program's bars match, including calls by position, by keyword and with keywords in a different order. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace the starter's progress_bar(3, 4, 8, "#") by hand: what are filled and percent, and what string does it return?

    filled = 3 * 8 // 4 = 6 and percent = 3 * 100 // 4 = 75, so it returns [######--] 75% (six # and two -).

  2. A teammate suggests the header def progress_bar(width=20, fill="#", done, total): so the options come first. What does Python do with it, and why does the rule make sense?

    Python refuses it with a SyntaxError (a parameter without a default follows one with a default). Arguments are matched by position, so if defaults came first, Python couldn't tell whether progress_bar(5, 10) meant width and fill or done and total. Required arguments must come first.

Solution

progress.py
"""progress.py - text progress bars for the course study tracker."""


def progress_bar(done, total, width=20, fill="#"):
    """Return a bar such as [##########----------] 50% for done out of total.
    width is the number of characters inside the brackets; fill draws the done part."""
    done = min(done, total)
    filled = done * width // total
    percent = done * 100 // total
    return "[" + fill * filled + "-" * (width - filled) + "] " + str(percent) + "%"


def main():
    """Ask for the progress and print it for three screens."""
    done = int(input("Lessons finished? "))
    total = int(input("Lessons in the course? "))
    print("Dashboard:", progress_bar(done, total))
    print("Phone:    ", progress_bar(done, total, width=10))
    print("Printable:", progress_bar(done, total, fill="="))


if __name__ == "__main__":
    main()

Walkthrough

Default arguments are assignments in the header: width=20, fill="#". They must follow the required arguments done and total; putting a default before a required argument is a SyntaxError. A call that omits them gets the defaults; a call that supplies them overrides them. The phone call may pass the width by position (progress_bar(done, total, 10)) or by keyword (width=10). The printable call has to use a keyword: to give a value for fill by position you would also have to repeat the width, 20, and repeating a default defeats the purpose. Keywords may come in any order (fill=".", width=8). done = min(done, total) caps the progress; an if done > total: statement works just as well. Assigning to the parameter done only changes the function's own copy: the caller's variable is untouched.

Messages students see when a check fails

C1 · width defaults to 20 and fill to "#", after the required arguments

Change the header to def progress_bar(done, total, width=20, fill="#"):. Required arguments come first; each default argument is written as an assignment.

C2 · progress_bar caps done at total

Before computing filled, limit done so it is never more than total, with min or an if statement. 12 of 10 should draw a full bar and 100%, not 24 characters in a 20-character bar.

C3 · The dashboard uses both defaults

Call progress_bar(done, total) for the dashboard. With defaults in the header, the most common call is also the shortest.

C4 · The phone call changes only the width

For the phone, pass just the width after the two required arguments, either by position (10) or by keyword (width=10). The fill keeps its default.

C5 · The printable call sets only fill, by keyword

To change the fill without restating the width, name it: fill="=". By position, the third argument always goes to width.

C6 · No call repeats a default value

Remove the explicit 20 and "#" from the calls. If the defaults change later, a call that repeats the old values won't follow.

Progressive hints

  1. Look at def example(required, option1 = 2, option2 = 3) in the reading: the required names come first, then each optional one is written as name = value.

  2. Before filled is computed, make sure done can't be bigger than total. Python's built-in min returns the smaller of its arguments.

  3. By position, values fill the parameters left to right, so the third value is always width. To skip the width and set only the fill, use the syntax <key> = <value> in the call.

Reflection: questions and model answers

  1. Why must the printable call use the keyword fill=, while the phone call may pass 10 by position?

    Positional values fill the parameters left to right, so a third value always goes to width. The phone changes width, the third parameter, so position works. The printable page changes only fill, the fourth; by position I would have to pass the width too, repeating the default 20. A keyword skips straight to fill.

  2. Inside your function, done = min(done, total) assigns to the parameter. Does this change the done variable in main? Explain using what the reading says about parameters.

    No. When the function is called, the argument's value is copied into the parameter, which is a variable of the function with the function body as its scope. Assigning to it changes only that copy, which disappears when the call ends; main's done still holds 12.

  3. Python's range has defaults too. Using the reading, explain what range(5) assumes, and how that compares with choosing 20 and "#" here.

    range(5) assumes a lower bound of 0 and a step of 1, because those are what most loops need. Our defaults follow the same idea: 20 and # are what most screens want, so the common call stays short, and the rare cases (phone, printable) override only what differs.
