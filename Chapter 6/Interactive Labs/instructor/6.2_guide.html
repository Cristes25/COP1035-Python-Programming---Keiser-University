COP1035 · Python Programming · Lab 6.2

Top-down design: the smart-light command checker

Objectives

  • Turn each rule of a design into one function, following a structure chart
  • Keep user interaction in main and the decision logic in the functions it calls
  • Test a top-down design bottom up, lowest-level functions first

Requirements

  1. R1 Define action(words): if fewer than 2 words remain it returns False; otherwise it removes the first two words and returns True only if they are a word from VERBS followed by a word from SWITCHES.
  2. R2 Define place(words): if no words remain it returns False; otherwise it removes the preposition and returns True only if it is in PREPOSITIONS and the words after it form an article and a room. Reuse article_noun for that second part.
  3. R3 command(words) returns True only for an action, a device and a place, in that order, with no words left over ("... in the lounge now" is rejected).
  4. R4 main handles only the conversation: it reads the text, calls command and prints the reply. It no longer inspects the words itself.
  5. R5 None of the grammar functions print anything or ask for input; they answer True or False.
  6. R6 The bottom-up test program's results match, from action up to main. (verified by the program output)

Before you code: warm-up and model answers

  1. Trace article_noun(["THE", "FAN", "IN"], DEVICES) by hand. What does it return, and what is left in the list afterwards? Why does it matter that the function removes the words it examines?

    It pops THE and FAN, returns True because THE is an article and FAN is a device, and leaves ['IN'] in the list. Removing the words matters because the next function in the chain (place) must start with the words after the device, not re-read the beginning.

  2. Run the starter with the program input. main currently decides on its own whether a command is valid. Name one command it accepts that it should reject, and say what it is checking instead of the grammar.

    It accepts "turn banana" (and "turn on the heater in the garage"), because it only checks that there are at least two words and the first is TURN. It ignores the device, the place and the vocabulary, and it rejects valid commands that start with SWITCH.

Solution

lights.py
"""lights.py - checks spoken commands for the residence hall's smart-light assistant.

Grammar of a valid command (one function per rule):
    command = action device place
    action  = verb switch            TURN ON, SWITCH OFF, ...
    device  = article device-noun    THE LAMP, A FAN, ...
    place   = preposition area       IN THE KITCHEN, AT THE DESK, ...
    area    = article room-noun
"""

# Data pool: the vocabulary every function looks up.
VERBS = ("TURN", "SWITCH")
SWITCHES = ("ON", "OFF")
ARTICLES = ("THE", "A")
DEVICES = ("LAMP", "FAN", "HEATER", "SPEAKER")
PREPOSITIONS = ("IN", "AT")
ROOMS = ("KITCHEN", "LOUNGE", "BEDROOM", "DESK")


def article_noun(words, nouns):
    """Given. Return True if the first two words are an article followed by
    a word in nouns, or False otherwise. Removes the words it examines."""
    if len(words) < 2:
        return False
    article = words.pop(0)
    noun = words.pop(0)
    return article in ARTICLES and noun in nouns


def device(words):
    """Given. device = article device-noun"""
    return article_noun(words, DEVICES)


def action(words):
    """action = verb switch. Return True if the first two words are a verb
    followed by ON or OFF. Removes the words it examines."""
    if len(words) < 2:
        return False
    verb = words.pop(0)
    switch = words.pop(0)
    return verb in VERBS and switch in SWITCHES


def place(words):
    """place = preposition area. Return True if the words start with a
    preposition followed by an article and a room. Removes the words it examines."""
    if len(words) == 0:
        return False
    preposition = words.pop(0)
    return preposition in PREPOSITIONS and article_noun(words, ROOMS)


def command(words):
    """Return True if words form one complete, valid command."""
    return action(words) and device(words) and place(words) and len(words) == 0


def main():
    """Take commands until the user presses return."""
    while True:
        text = input("Command (press return to quit): ")
        if text == "":
            return
        words = text.upper().split()
        if command(words):
            print("Done.")
        else:
            print("Sorry, I don't understand that command.")


if __name__ == "__main__":
    main()

Walkthrough

Each grammar rule becomes one function that receives the remaining words and returns a Boolean, exactly like nounPhrase and verbPhrase in Case Study 6-1. pop(0) both reads and removes a word, so each function hands the rest of the list to the next one; that is why command can simply chain the calls with and. Short-circuit evaluation stops at the first False, so a bad action never gets as far as device. The length guards (< 2, == 0) protect pop(0) from an IndexError on short input. place reuses article_noun(words, ROOMS): the same general method with a different vocabulary, so the article check lives in one place. len(words) == 0 at the end of command rejects trailing words (the book's recognizer doesn't check this; not words is also fine). main now has one responsibility, the interaction, while the grammar functions own the decision: responsibility-driven design. A new room or device is a one-word change to the data pool.

Messages students see when a check fails

C1 · action is defined with one parameter

Add the header def action(words): where the TODO (R1) comment is. Each grammar function receives the list of words that are left.

C2 · action guards against short input

Before taking two words, check the length: if fewer than 2 words remain, return False. Without the guard, action(["TURN"]) crashes with an IndexError instead of answering.

C3 · action removes two words and checks both vocabularies

Take the verb and the switch with words.pop(0) (twice), then return whether the verb is in VERBS and the switch is in SWITCHES. Popping matters: device must receive the words after the action.

C4 · place is defined with one parameter

Add the header def place(words): where the TODO (R2) comment is.

C5 · place guards against an empty list

If no words remain, return False before popping. "TURN ON THE LAMP" reaches place with an empty list.

C6 · place checks the preposition and passes the rest to article_noun

Pop the preposition, then return whether it is in PREPOSITIONS and article_noun(words, ROOMS). Let article_noun check the article: when in doubt, pass the task to the function that already knows how.

C7 · command adds the place and rejects leftover words

Chain place(words) after device(words) with and, then add one more condition: the list must be empty at the end (len(words) == 0). Otherwise "turn on the lamp in the lounge now" passes.

C8 · main asks command instead of judging the words itself

Replace the if len(words) >= 2 and words[0] == ... test with if command(words):. main owns the conversation; the grammar functions own the decision.

C9 · action doesn't print or ask for input

Return True or False and let main decide what to say. A function that prints can't be reused quietly, for example by a test program or a future app screen.

Progressive hints

  1. article_noun is your model for action: guard the length, pop two words, return one Boolean expression that checks both.

  2. place is shorter than it looks: one guard, one pop(0), and a return that combines preposition in PREPOSITIONS with a call to the given article_noun, passing the list of rooms.

  3. After action, device and place have each popped their words, what should be left in words for a perfect command? Add that as the last condition in command.

Reflection: questions and model answers

  1. Your test program checks action and place before command, and command before main. Why is this bottom-up order a better way to find bugs than running main and typing commands?

    Each function is tested only after the functions it depends on are known to work, so when a test fails the bug is in the function just tested. Running main first, a wrong answer could come from any of five functions and I would have to guess which one.

  2. Using the structure chart, describe the job of main and the job of command in one sentence each. What would break if main went back to checking words itself?

    main handles the conversation: it reads the text, prepares the words and prints the reply. command decides whether the words are a valid command by delegating each part to action, device and place. If main checked words itself, the grammar would live in two places, they would disagree, and changing the rules would mean editing main too.

  3. The hall adds a new room, HALLWAY, and a new verb, PUT. Which lines of your program change, and why so few?

    Only the data pool: add HALLWAY to ROOMS and PUT to VERBS. The functions look words up in the pool instead of containing them, so the vocabulary can grow without touching the logic.

Extension

Extend the grammar so the place is optional: TURN OFF THE FAN alone is valid and means 'everywhere'. Change only command, and add two lines to the test program that prove both forms work.
